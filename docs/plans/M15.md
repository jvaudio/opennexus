# M15 · Export to Xmind

## Plan

**Goal (Xmind parity review):** OpenNexus imports `.xmind` files but couldn't write them,
so people working with Xmind users couldn't send a file back. Write a modern Xmind file
with everything Xmind can hold, and say what it can't.

**Accept when:**
- **A1 · The file:** a modern Xmind (2020 and later, "Zen") file: `content.json`,
  `metadata.json` and `manifest.json`, plus `content.xml` only if needed for
  compatibility. One sheet per canvas.
- **A2 · Content:** topics, structure, notes, labels, markers (mapped back where an
  equivalent exists), relationships, boundaries, summaries, images, comments, legends and
  task info (M11). The theme is approximated or left as Xmind's default.
- **A3 · Round trip:** OpenNexus → .xmind → OpenNexus keeps topics, structure, notes,
  labels, relationships, comments, legends and task fields.
- **A4 · Well formed:** the zip and its JSON are valid; the sample Xmind fixtures in
  Tests survive a re-export.
- **A5 · Where:** the export sheet, and `nexus export --to xmind`.
- **A6 · Honesty:** what doesn't survive is listed in an export report and in this file.

### The writer (NexusInterchange)

- **`XmindWriter.export(doc, thumbnail:, timeZone:)`** returns the archive and an
  `ExportReport`. It's written by hand with `ZipWriter` (D89) and `JSONSerialization`
  with sorted keys, so the same document always gives the same bytes.
- **The archive** (D166, D167):

  | Path | Holds |
  | --- | --- |
  | `content.json` | one sheet per canvas |
  | `metadata.json` | creator (OpenNexus), data-structure and layout-engine versions, the active sheet |
  | `manifest.json` | `file-entries` for everything Xmind reads |
  | `resources/<asset>` | topic images |
  | `attachments/<asset>` | a topic's first attachment |
  | `Thumbnails/thumbnail.png` | the first canvas, at most 600 px wide (from the app and CLI) |
  | `content.xml`, `META-INF/manifest.xml` | a notice for XMind 8: open this in Xmind 2020 or later |

- **Ids** are `<canvas>-<topic>` (`c1-n3`), sheets `sheet-<canvas>`, so relationships,
  summaries, dependencies and topic links point at stable ids.

### Mapping

| OpenNexus | Xmind |
| --- | --- |
| Canvas | sheet (`title`, `rootTopic`, `relationships`, `legend`, the skeleton extension) |
| Topic text, note | `title`; `notes.plain` and `notes.realHTML` (a `<div>` per line) |
| Labels | `labels` |
| Markers | `markers` (`priority-N`; progress → `task-start`, `task-quarter`, `task-half`, `task-3quar`, `task-done`; flags; `star-yellow`, `star-red`, `star-blue`; `symbol-question`, `symbol-exclam`, `symbol-right`, `symbol-wrong`, `arrow-right`; `people-red`, `people-blue`) |
| Web or file link | `href` |
| Topic link | `href: "xmind:#<id>"` (also reaches other sheets) |
| Image | `image.src: "xap:resources/…"` with width and height |
| First attachment | `href: "xap:attachments/…"` when the topic has no link |
| Folded | `branch: "folded"` |
| Floating topic | `children.detached` with `position` |
| Summary | `children.summary` and `summaries[{range, topicId}]` on the parent |
| Callout | `children.callout` on the host |
| Boundary | `boundaries[{range, title}]` on the parent (`(i,j)`), or `master` around a central or floating topic |
| Relationship | `relationships[{end1Id, end2Id, title}]` |
| Comments | `comments[{author, content, creationTime}]` |
| Legend | `legend{visibility, position, markers{id: {name}}}` |
| To-do and task | extension `org.xmind.ui.task`: `status`, `start`, `due`, `assignee`, `progress`, `dependencies[{id, type, lag}]` (D168) |

**Structures** (the canvas's, and any branch's own):

| OpenNexus | Xmind class |
| --- | --- |
| Mind map (balanced, right, left) | `map.unbalanced`, `map.clockwise`, `map.anticlockwise` |
| Logic (right, left) | `logic.right`, `logic.left` |
| Brace (right, left) | `brace.right`, `brace.left` |
| Org chart | `org-chart.down` |
| Tree (indented) | `tree.right` |
| Tree (down) | `org-chart.down` (approximated, reported) |
| Timeline (horizontal, vertical) | `timeline.horizontal`, `timeline.vertical` |
| Fishbone (left, right) | `fishbone.leftHeaded`, `fishbone.rightHeaded` |
| Tree table, matrix | `treetable`, `matrix` |
| Flowchart, graph, swimlanes, sequence | `logic.right` (approximated, reported) |

**Task dates** are epoch milliseconds at noon on the day in the exporting Mac's time zone,
so a reader up to 11 hours away sees the same day. Days before March 1973 are written as
ISO 8601, because the importer reads smaller numbers as seconds (D149).

### What doesn't carry over (the export report)

- The theme, colours and topic shapes (Xmind applies its default theme), topic styles and
  quick styles, and rich text formatting.
- Zones (their topics are kept), stickers, audio notes, data fields, and attachments after
  the first (or any, when the topic has a link).
- Markers without an Xmind equivalent (`people-external`, custom ids), and legend
  descriptions for them.
- Technical-diagram data: node types, edge labels, lanes, DFD levels and rule settings;
  technical layouts become a logic chart.
- Relationship line, arrow and colour styles; boundaries around topics under different
  parents (left out), or not next to each other (widened).
- Topics under a callout, saved filters, the work calendar, AI chats.

The export sheet shows the list under the description, and saving shows "Saved for Xmind
2020 or later · 3 items not carried over".

### In the app and the CLI

- **The export sheet:** Xmind in STRUCTURAL, with a canvas preview, a "2 sheets · 31
  topics" line, a description and the NOT CARRIED OVER list.
- **`nexus export --to xmind`** and the MCP `export` tool, through the same exporter.

### Importer changes for the round trip (D169)

- Xmind's default map class, `org.xmind.ui.map.unbalanced`, has branches on both sides; it
  imported as right-only and now imports as balanced. `map.clockwise` is the right-hand map.
- A `master` boundary is around the topic's own branch, not its children.
- An XMind 8 central topic's structure class sets the canvas's structure only, as in Zen.

### Built

- **NexusInterchange:** `XmindWriter` and `ExportReport` (`XmindExport.swift`); importer
  corrections in `Xmind.swift`.
- **NexusCanvas:** `ExportFormat.xmind`, the sheet's Xmind section, the thumbnail and the
  save toast.
- **NexusAgent:** `CLIFormat.xmind`.

### Changed from the plan

- **`content.xml` is written**, but only as a notice for XMind 8, with a
  `META-INF/manifest.xml` so XMind 8 opens it (D167).
- **The importer changed** in three places so the round trip keeps structure and
  boundaries (D169). The `zen.xmind` and `xmind8.xmind` import goldens changed by one line
  each.

### Defects found during M15 and fixed

- **Xmind's default mind map imported as right-only** (`map.unbalanced`).
- **A `master` boundary imported around the topic's children** instead of its branch.
- **The XMind 8 central topic kept a structure override** equal to the canvas's.
- **A task date before 1973 would have re-imported in 1971:** the epoch millisecond value
  is under the importer's seconds threshold, so those dates are written as ISO 8601.
