# M47a · Platform split

The first of M47's four parts (`collaboration-and-reach.md`, Phase 5): the code that
draws a map and the code that edits one stop depending on AppKit, so the iPad and iPhone
app (M47b, M47c) can share them. Nothing changes for the Mac user.

Decision #12 (iOS/iPadOS 27, TestFlight then the App Store) was confirmed on Oct 29, 2026
(D378).

## What we know before starting

- `NexusCanvas` imports AppKit in 67 of its 100 files. The controller itself barely uses
  it: the pasteboard, two appearance reads, the user's name, one VoiceOver announcement
  and two popover anchors. The coupling is indirect. Scenes are measured with `NSFont`
  and TextKit; every export renders an offscreen `CanvasView` in a borderless `NSWindow`;
  a few controller members live in view files.
- **Fonts.** The faces AppKit builds (system, serif, rounded and monospaced designs at all
  five weights, italics, Noteworthy) are system UI font descriptors that CoreText can
  build directly. Over 375 styles, CoreText built the same face as AppKit every time
  (same PostScript name, variation axes and metrics).
- **Text engines** were measured over 599 titles × 375 styles (74,875 cases) with the
  measurer's own algorithm:
  - CoreText against TextKit on the Mac: 95.0% give the same size. TextKit's string
    drawing shortens each line by the baseline offset that centres glyphs in tall lines
    (up to 3 pt), so long topics round to a different line count. Widths include
    trailing spaces and are clipped to the wrap width.
  - TextKit on the iPad simulator against TextKit on the Mac: 98.3% the same. What
    differs are the fonts themselves (iOS has `.SFUI`, macOS `.SFNS`), and no engine
    can fix that.
- So text goes through the platform's own string drawing (TextKit on both), which keeps
  the Mac's output identical and makes iPad and Mac lay maps out as alike as their fonts
  allow. CoreText is the fallback anywhere else.

## Plan

### `NexusScene` (new; no AppKit or UIKit)

Everything that turns a document into pictures, on CoreGraphics, CoreText and QuartzCore.
It depends on NexusCore, NexusLayout, NexusTheme and NexusFormat.

- **Text.**
  - `TextStyle` and `StyledText`: runs of text with a `CTFont`, a `CGColor`, a baseline
    offset, kerning, underline, strikethrough, a link and a highlight, plus the
    paragraph's alignment, line height and line breaking.
  - `TextSystem` is the one place text is measured and drawn: a bounding rect at a wrap
    width, the size of a single line, and drawing in a rect or at a point.
  - Fonts are built with CoreText from the system's UI font descriptors. That covers the
    weights, the serif, rounded and mono designs, italic and bold marks by symbolic
    traits, families by name and weight, and the CJK cascade list.
  - `CoreTextSystem` is the built-in engine. The Mac installs a TextKit engine at
    startup; NexusTouch will install UIKit's in M47b.
  - System colours (label, secondary label, accent, teal, red) resolve through the same
    platform hook, so they keep following the current appearance.
- **Moves in, rewritten off AppKit:**
  - `Scene`, `SceneBuilder` and `SceneTechnical`;
  - `NodeTextStyle` and `NodeMeasurer`; `RichFormats` (math and code);
  - the layers (`NodeLayer`, `DecorLayer`, the element layers, `DecorRenderer`, the
    legend layer, the grid);
  - `Animator`; the Gantt layout and renderer; the minimap's renderer;
  - `Loc` and the string catalog.
  - The translations: NSColor → CGColor, NSFont → CTFont, NSBezierPath → CGPath,
    NSImage icons → CG drawing, NSGraphicsContext → the CGContext.
- **`SceneRenderer`**: the layer tree that `CanvasView` builds today, kept in step with a
  scene, with the same z-order and the same per-topic, edge, cap, element, decor and
  legend updates. It covers the camera, culling, text scale and the spring animations,
  stepped by whoever hosts it.
  - `CanvasView` hosts it on the Mac, and the iPad canvas will host the same one.
  - Exports host it with no view or window: final frames, export mode, Reduce Motion.
- **Exporters, from a scene:**
  - render a scene to a `CGImage`;
  - SVG; slide images with their kicker, title and extras;
  - print pages; Gantt images;
  - PDF, PPTX and video packaging; the viewer bundle's per-canvas JSON;
  - HTML packaging.
  - Building the scene for an export stays with the controller (below), so an export
    still matches what the window shows.
- **Images.** Assets decode through the platform hook; PNG and JPEG encode with ImageIO.

### Editing logic (`NexusCanvas`, now buildable for iOS)

- `CanvasController` and its extensions, `DocumentStore`, `Preferences`, the starter and
  guide catalogues and the export entry points stay in NexusCanvas, which has to compile
  for iOS.
- Mac-only code is compiled under `#if os(macOS)`: views, sheets, popovers, AppKit
  bridges, the XPC transports, the Keychain store and security-scoped bookmarks.
- **`CanvasHost`** is what the controller asks of its platform:
  - the pasteboard (`CanvasPasteboard`, mirroring the names it uses today);
  - whether the system is dark and whether it asks for more contrast;
  - the user's name and the device's name;
  - VoiceOver announcements.
  - The Mac's host wraps NSPasteboard, NSApp and NSWorkspace. Tests use a memory host.
- Things that move rather than go behind the host:
  - the popover anchors move to the popover layer;
  - legend, strip and present members that live in view files move to controller files;
  - `ganttColors` returns `RGBA`;
  - pasted bitmaps go through ImageIO;
  - the language guess moves to NexusAI;
  - `CodeLinks.open` and the starter thumbnails move to the Mac side;
  - the share, sync and collaboration centres take their transports and secret store
    from whoever builds them.

### `NexusAI`

`MediaAI` encodes PNGs with ImageIO instead of `NSBitmapImageRep`. NexusAI then builds
for iOS, where Foundation Models, Vision, Translation, Speech and Image Playground exist.

### `NexusKeys`

- `KeyChord(hidUsage:modifiers:characters:)`: the pure mapping from USB HID usages
  (which `UIKey.keyCode` reports) to keys. It is testable on the Mac against the
  `NSEvent` mapping.
- `KeyChord+UIKey` beside `KeyChord+NSEvent`, compiled for iOS.

### Checks

- `scripts/lint.sh` fails if NexusScene or anything below it (NexusCore, NexusLayout,
  NexusTheme, NexusFormat, NexusKeys), or NexusAI, imports AppKit, UIKit, Cocoa,
  Carbon or SwiftUI.
- `scripts/build-ios.sh` builds the shared modules for the iOS Simulator with
  `xcodebuild`:
  - NexusCore, NexusLayout, NexusFormat, NexusTheme, NexusKeys, NexusScene, NexusAI;
  - NexusInterchange, NexusSync, NexusReplica and NexusCanvas.
- `Package.swift` adds iOS 27 to its platforms.

### WebAssembly spike (time-boxed)

- Build NexusCore, NexusLayout, NexusTheme and NexusScene's scene and builder (not its
  layers, which need QuartzCore) for WebAssembly with the Swift SDK. Text is measured
  by a pluggable measurer fed by canvas text metrics.
- Measure:
  - the size of the `.wasm`;
  - the time to lay out 1,000 topics;
  - text-metric drift against the Mac.
- Record whether the browser should lay maps out itself.
- **This needs the swift.org toolchain and the WebAssembly Swift SDK** (user-level
  installs, about 2 GB). Jerry has to approve them before the spike runs.

### Tests

- NexusSceneTests:
  - fonts equal AppKit's;
  - the CoreText engine against TextKit over the corpus (the parity is recorded, not
    required to be 100%);
  - `StyledText`;
  - a scene rendered without a view equals the canvas's own render.
- NexusCanvasTests: every existing test unchanged in meaning, including the 36 style
  goldens, the exporter goldens, the pixel checks and the SVG strings. The controller
  runs with a memory host.
- NexusKeysTests: HID usages against the NSEvent mapping, for every key either one knows.
- The iOS build script, and the lint rule shown failing on a planted import.

### Built

- **NexusScene** (new; CoreGraphics, CoreText, QuartzCore, ImageIO; no AppKit or UIKit):
  `Fonts`, `StyledText` with `TextKey`, `TextParagraph` and `TextColorValue`, the
  `PlatformGraphics` hook and `CoreTextGraphics`; `NodeTextStyle`, `NodeMeasurer` and
  `RichFormats`; `Scene`, the builder, `SceneTechnical`, the Gantt layout and renderer,
  `Minimap`, `MarkerLibrary`, the connect state and task formats; the layers (`NodeLayer`,
  the element layers, `DecorRenderer`, `LegendLayer`) and `Animator`; `SceneRenderer`,
  which `CanvasView` and the exporters host; `Loc` and the string catalog.
- **NexusCanvas** builds for iOS. The Mac's views, sheets, popovers, AppKit bridges, XPC
  transports and Keychain store are compiled under `#if os(macOS)`. `CanvasHost` with
  `MacCanvasHost` (which installs `AppKitGraphics`, the TextKit engine) and
  `MemoryCanvasHost`; `CanvasPasteboard` with `MacPasteboard` and `MemoryPasteboard`;
  `PopoverAnchors` for the outline and Gantt anchors; `PlatformNetwork` and `NoNetwork`;
  the share, sync and collaboration centres take their transport and secrets. Exporters
  encode with ImageIO. The language guess is `MapTranslator.language(of:)` in NexusAI.
- **NexusInterchange**: `MiniXML` for iOS (D384).
- **NexusAI** encodes PNGs with ImageIO and builds for iOS.
- **NexusKeys**: `KeyChord(hidUsage:modifiers:characters:)`; `KeyChord+UIKey` for iOS.
- **Checks**: the import rule in `scripts/lint.sh`; `scripts/build-ios.sh`.
- **Tests**: NexusSceneTests (`FontTests`, `TextEngineTests` with the 599-title corpus,
  `StyledTextTests`); `SceneRendererTests`, `RenderDefectTests` and `KeyChordHIDTests` in
  NexusCanvasTests; `HIDTests`; `MiniXMLTests`. The controller tests run on a memory host.

### Changed from the plan

- **`scripts/build-ios.sh` uses SwiftPM's cross-compile, not `xcodebuild`** (D382).
- **The text engine is found by its Objective-C name** as well as installed (D379), so the
  CLI, the Quick Look extensions and the tests draw with TextKit without a host. The plan
  had the Mac install it at startup only.
- **`PlatformGraphics` has two more hooks than planned:** `coreTextString`, for the SVG
  writer, which lays text out with CoreText itself and must see AppKit's attributes on the
  Mac; and `drawPicture`, so icons drawn by closures are cached at the destination's
  resolution as `NSImage` drew them, keeping their pixels.
- **Exports render with a backing scale of 1**, times their own scale, whatever the display (D380).
- **`Fonts.lineHeight` replaces `NSLayoutManager.defaultLineHeight`:** TextKit's value is
  the font's ascent, descent and leading each rounded, checked for every size from 8 to 72.
- **The HID cross-check lives in NexusCanvasTests**, beside the `NSEvent` mapping it
  compares with; NexusKeysTests checks the HID table alone.
- **The string catalog moved to NexusScene** (D381), and the app's build phase with it.
- **`ChromeText` is split:** its scale and range are shared; the SwiftUI and AppKit fonts
  are Mac-only.
- **XML reading needed `MiniXML`** on iOS (D384), and swift-format stopped indenting `#if`
  blocks (D385). Neither was foreseen.
- **iOS gets `NoNetwork` and memory secrets for now** (D383).
- **The WebAssembly spike built NexusCore, NexusLayout and NexusTheme, not NexusScene's
  scene and builder:** those are written against `CTFont` throughout, and making fonts
  abstract was more than a time-boxed spike. The measurer the browser would need (wrapping
  as NodeMeasurer does, from canvas word widths) was written in the spike instead. Like the
  text spike, its code isn't kept in the repository; A8 records how it was measured.
- **PPTX slide images are encoded by ImageIO**, so their PNG bytes differ from
  `NSBitmapImageRep`'s; the pixels are the same, and no golden compares PPTX bytes.

### Defects found

- **The sketch style's wobble changed every launch.** Its seed was `hashValue`, which
  Swift randomises per process; it's a stable hash of the topic id now
  (`sketchWobbleIsTheSameEveryLaunch`).
- **Printing in Dark Mode drew white text** on white paper, and the notes appendix could
  fall outside the page (`printTextIsDarkAndOnThePageInDarkMode`).
- **Exports depended on the display:** text rasterised at the screen's backing scale, so a
  Retina and a non-Retina Mac made different PNGs (`exportTextRasterisesAtTheExportScale`).
- **The headless Gantt export took the system appearance** whenever the app was running
  (`headlessExportsIgnoreTheAppAppearance`).
- **Topic text layers' `contentsScale` was never initialised**, and captions didn't follow
  the text scale (`topicTextStartsAndStaysAtTheTextScale`).
- **A `SceneRenderer` without a view had no bounds**, so its root drew no canvas colour;
  found by A4's comparison.
- **The CoreText engine** (not used on the Mac) drew `draw(at:)` text below its point in
  unflipped contexts, measured single lines by their glyphs rather than TextKit's line box,
  and resolved system colours through whichever engine was installed. Found by
  `TextEngineTests`; it now lands within a pixel of TextKit.

### Known gaps

- **iPad-against-Mac text parity was measured once in the simulator, by hand**; M47b's
  NexusTouch tests can make it a test.
- **NexusCanvas on iOS compiles but isn't wired:** no network (D383), a memory host, and
  security-scoped bookmarks only on the Mac. M47b supplies the iPad's.
- **The CoreText engine still lays out multi-line text without a fixed line height by
  CoreText's own line spacing**; every topic has a fixed line height, so maps don't hit it.
- **No layout in the browser** (D386): folding with reflow, files without a viewer copy,
  M47d's live view of a session and M49's map without the app wait on it.
