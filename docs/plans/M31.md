# M31 · Xmind remaining gaps

## Plan

**Goal (Xmind parity, from M23's and M25's known gaps):** close what the real-file check
(M23) and the style milestone (M25) left open.

1. Xmind data OpenNexus doesn't use (the Pitch extension, unknown topic and sheet
   extensions, `compactLayoutModeLevel`, `arrangeableLayerOrder`, `topicOverlapping`) was
   reported or ignored, so re-saving an Xmind file in OpenNexus reset it.
2. Theme topic classes on XMind 8 files weren't imported as Zen's are.
3. Xmind's `importantTopic`, `minorTopic` and `expiredTopic` classes weren't read or
   written.
4. New boundaries, summaries and relationships after an import used OpenNexus's defaults,
   not the imported theme's (D221).
5. Progress markers in eighths rounded to quarters.

**Accept when:**
- **A1 · Kept:** a stand-in shaped like the roadmap sample (Pitch on the central topic, an
  unknown topic extension, `numbering`, compact mode, overlapping, Gantt settings, a layer
  order naming a floating topic, a relationship, a boundary and a missing id) imports with
  nothing reported, goes through `.nexus`, and exports with every key and extension back
  and the layer order in this file's ids. A second trip changes nothing; deleting an
  element drops its layer entry.
- **A2 · XMind 8 themes:** a stand-in with XMind 8's spellings (lower-case hex, styles in
  `automatic-styles`, the theme in `master-styles`, `svg:fill="none"`, no branch colours, a
  sheet style) imports with its background, branch colour, font, topic classes and element
  classes, and looks the same after `.xmind` and XMind 8 exports.
- **A3 · Quick style classes:** topics with the three classes import as Very important,
  Important and Cross out, drawn with the theme's classes; OpenNexus's quick styles export
  as the classes, which bring them back even without OpenNexus's record.
- **A4 · Element defaults:** another app's element classes become the canvas's defaults;
  new elements and Reset Style take them, the canvas draws uncoloured elements in the
  default's colour, and the `.xmind` and XMind 8 round trips keep both the defaults and
  each element. Both schema copies list the new fields; files without them are unchanged.
- **A5 · Eighths:** Xmind's four eighths import and export exactly, `progress(of:)`
  reads them, the legend names them, and they draw as pies.

### Approach

- **Kept data:** `extra["xmind"]` on the canvas and nodes (`keys`, `extensions`,
  `layerOrder`), where `.nexus` already keeps unknown keys. Layer order entries go through
  the builder as `{"sourceRef": id}` and come out as this file's elements.
- **Element defaults:** `CanvasStyle.elements` (`ElementStyles`), adopted on creation and
  import, with colours resolved in `SceneBuilder`, the way `roles` work for topics.
- **Quick styles:** `CanvasStyle.quickStyles` replaces built-in quick styles' looks in
  `StyleEnvironment`, so the resolver, Format panel and exporter need nothing else.
- **Markers:** `MarkerLibrary.Marker.pie`, drawn by `LegendLayer.drawPie` (topics and the
  legend), `ProgressPie` (the picker) and `SVGExporter.pieMarker`.

### Known gaps

- **Unverified in Xmind itself.** No Xmind was available, so these are taken on trust:
  - that a topic's `class` is written `"topic importantTopic"` (the reader accepts the
    class alone too) and that Xmind's Very important / Important / Cross out are
    `importantTopic` / `minorTopic` / `expiredTopic`;
  - the shape of `arrangeableLayerOrder` entries: ids and objects with an `id` are
    handled; any other entry is dropped;
  - that XMind 8 writes `svg:fill="none"` for no fill and leaves `multi-line-colors` out
    or `none` when branches share one colour.

  `XmindRealFileTests` on the roadmap sample, re-saved, is the check for A1.
- **No UI for element defaults** (D246): they come from an import only.
- **XMind 8 export** still writes Zen's `fill-pattern` for "no fill" and a branch-coloured
  fill, which XMind 8 doesn't read, and leaves out the kept Xmind 2020 data (reported).
- **Not kept:** an attached topic's free `position`, unknown keys on relationships,
  boundaries and summaries, and XMind 8 extensions other than task info (still
  reported). Xmind zones still don't import (now reported).
- **Pasting or copying between canvases** keeps a node's kept Xmind data with it; an
  element pasted into a canvas with element defaults keeps its own fields (only its
  colour follows the defaults, when it has none).
