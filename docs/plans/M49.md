# M49 · Obsidian plugin

Phase 7 of `collaboration-and-reach.md`: OpenNexus maps in Obsidian vaults. The plugin
opens maps read-only, embeds them in notes, follows their links into the vault, hands a
map to the Mac app to edit, and shows any Markdown note as a map. It's built on M43's
viewer (`web/viewer-core`) and the viewer copy saved in documents (D314).

Decision #15 was confirmed on Oct 31, 2026: releases are mirrored to
`jvaudio/opennexus-obsidian`, as Obsidian's community directory expects (D451). The same
day Jerry chose to check Obsidian for iOS by hand himself, from a checklist in the test
vault; the desktop check is automated (D452).

## What we know before starting

- **The viewer** (`viewer-core`): `mount(host, bundle, {asset, chrome, actions})` draws a
  bundle with its bar, outline, details and Present; `chrome: "none"` is the map alone
  (M47d). Details show a topic's link as a link only for http(s) and mailto, and notes as
  plain text. It has no way to tell its host what's selected, frame a branch, or keep the
  camera across a redraw. `viewer.css` starts with `html, body` rules for the export's
  page, which mustn't reach Obsidian's own UI.
- **Viewer copies:** a package's `render/viewer.json` (assets in `assets/`), and a
  `.nexusjson`'s `render` key (base64 assets) only when "Also in single-file documents" is
  on (D314). The site already reads both and falls back to the outline (M47d, D446).
- **`nexus`** ships inside the Mac app (`Contents/Helpers/nexus`) and isn't sandboxed.
  `nexus import` reads Markdown through `MarkdownFormat.parse`, which keeps no source line
  numbers; `MapFiles.write` adds the viewer copy only when the CLI's own preferences ask.
- **Obsidian:** 1.9.12 is installed here (its profile has 1.15.0's update). The `obsidian`
  package's newest types are 1.14.4. Obsidian treats a `.nexus` package as a folder. A
  second Obsidian started with `--user-data-dir` and `--remote-debugging-port` runs beside
  the user's own with its own profile and vault, and Playwright reaches it over CDP
  (checked; `_electron.launch` doesn't start it).
- **A crafted bundle** (M43's `malicious` fixture) already renders inert in the HTML
  export; the site and Obsidian haven't been tried with one.

## Plan

### Swift

- **`nexus bundle <file|->`** prints a viewer bundle: of a map (its viewer copy, as the app
  saves it), or of Markdown (a `.md` file, or stdin with `-`) read as `nexus import` reads
  it, with `--structure` and `--title`. A Markdown bundle carries `lines`, each topic's
  source line; `viewer.schema.json` gains it as optional, so version 1 stands.
- `MarkdownFormat.parse` can record each heading's and bullet's line (off for import).
- `nexus import --viewer-copy` writes the viewer copy into the map it makes, a
  `.nexusjson` included, so a converted note shows on Obsidian for iOS too.

### viewer-core

- **Host options:** `hostLinks` (links the host opens itself: hyperlinks it accepts, and
  `[[wikilinks]]` in notes, as buttons; the viewer never navigates to them), `onSelect`
  (the selected topic, for Copy link and the editor's cursor), and on the handle
  `focus(topic)` (frame a branch), `view()` and `setView()` (keep the camera across a
  redraw).
- The page's `html, body` rules move to their own file that only the export and the site
  include; the built CSS stays byte-identical.

### The plugin (`web/obsidian`)

- **Map view** for `.nexusjson` (`registerView`, `registerExtensions`): the viewer copy;
  without one, `nexus bundle` on macOS, else the outline (the site's fallback) with how to
  turn the copy on. "Open as OpenNexus map" in the folder menu for `*.nexus` folders reads
  `render/viewer.json` and `assets/`. Both reload on vault changes to the file (debounced).
- **Embeds:** ```` ```nexus ```` with `file:`, `canvas:`, `topic:` (id, title or
  `A > B`), `layout:` and `height:`, in Reading view and Live Preview; the map alone, with
  pan, zoom and an Open link. Each starts when scrolled into view and is torn down with
  its section.
- **Links:** wikilinks and `obsidian://open` links in notes and hyperlinks open vault notes
  through the workspace API. "Copy link to topic" copies
  `obsidian://opennexus?file=…&canvas=…&topic=…`, which reopens the map at the topic.
- **Edit in OpenNexus** (view button and command; desktop macOS only): `open -b
  com.opennexus.OpenNexus <file>`; the view reloads when the app saves.
- **Note as map:** a side view of the active note through `nexus bundle -` (stdin),
  updated 400 ms after typing stops, keeping the camera. Clicking a topic moves the
  editor's cursor to its line. Elsewhere it shows the note's outline.
- **Conversions:** "Convert note to OpenNexus map" (`nexus import --viewer-copy`, a
  `.nexusjson` beside the note); "Insert map as outline" (`nexus export --to markdown`, or
  the viewer copy's outline without the app).
- **Settings:** the `nexus` path (found automatically), default layout, embed height, and
  whether the viewer follows Obsidian's theme.
- No network requests, no HTML from strings, and everything registered through
  `register*` so unload cleans up; ESLint rules enforce the first two.

### Release

- `scripts/release-obsidian.sh` builds, checks the size and that `manifest.json`,
  `versions.json` and `package.json` agree, and writes `dist/obsidian/<version>/` (the three
  assets and a zip). With `--publish` it mirrors `web/obsidian` into
  `jvaudio/opennexus-obsidian` (manifest at the root), tags the version and creates the
  GitHub release; it stops with instructions if that repo doesn't exist yet. I won't run
  `--publish`.

### Tests

- **Swift:** `nexus bundle` (a map, Markdown from a file and stdin, structures, lines,
  equal to `nexus import`'s map), `import --viewer-copy`, and parse lines.
- **Vitest:** the plugin against a mocked `obsidian` module (registration and clean unload,
  the code block's options, link routing, finding `nexus`, readers), and the new viewer
  options.
- **Playwright, Obsidian** (a project of its own, skipped when Obsidian isn't installed):
  a copy of `web/obsidian/test-vault/` with the release assets installed, in a throwaway
  Obsidian; view, package, embeds (lazy), links, live reload, note as map, conversions and
  the crafted bundle.
- **Playwright, site:** the crafted bundle opened from the front page.

### Changed from the plan

- The desktop check is automated rather than done by hand: a throwaway Obsidian over CDP
  (D464). Saves come from `nexus mcp` rather than the app, through the same writer
  (`MapFiles.write`). The CLI saves a `.nexusjson` without `render` unless the user asked for
  one in single files, so that redraw goes through `nexus bundle`.
- The release script gained `--install`, for A5 and for setting up the iOS check.
- A topic link to a map that isn't in the vault now says so; the plan didn't say.
- Settings gained the layout for notes as maps; embeds take `everything` for `expanded`.
- A3's "equals `nexus import`" is checked twice: in Obsidian against the map Convert note
  makes, and in the test against `nexus import` run directly.
- Embeds carry `data-opennexus-file`, which the tests use to tell them apart.

### Defects found

- **Obsidian styles every button,** so links in notes and details had borders and padding
  in Obsidian; they have their own style now (D462).
- **The package view's header said "OpenNexus map":** Obsidian sets an item view's header
  title once, as it loads, before the path is known. Set after opening (D456).
- **A topic link to a missing map did nothing;** it gives a notice now (D458).
- **`await import("child_process")` stayed native in the bundle,** which Obsidian's loader
  can't run; Node's modules load with `require` (D459). Found while building, before the
  e2e.
- **`file: Plan.nexus` found nothing:** links don't reach folders, so the embed also looks
  for a package by name (D457).
- Five lines of the new Swift were over the length limit (`lint.sh`); formatted.
- In the tests, not the plugin: macOS draws Obsidian's menus outside the page (native menus
  are off in the test vault); Obsidian carries a note's scroll position from Reading view to
  Live Preview; `Trip.md` ends in a newline, so the typing test types a list item.
