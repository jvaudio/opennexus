# M47b · iPad

The second of M47's four parts (`collaboration-and-reach.md`, Phase 5): OpenNexus on the
iPad, with the same maps, keyboard flow, on-device AI, sharing, sync and co-editing as the
Mac, on the code M47a split out. The iPhone's compact layout is M47c.

Decision #12 (iOS/iPadOS 27, TestFlight then the App Store) was confirmed on Oct 29, 2026
(D378). No other decision in the plan's table is needed by M47b.

## What we know before starting

- After M47a, NexusCore, NexusLayout, NexusFormat, NexusTheme, NexusKeys, NexusScene,
  NexusAI, NexusInterchange, NexusSync, NexusReplica and NexusCanvas build for the iOS 27
  Simulator. On iOS, NexusCanvas has a memory host, no network (D383) and CoreText as its
  text engine.
- The Mac's canvas (`CanvasView`, 2,000 lines) hosts a `SceneRenderer` and keeps the
  mouse logic (drag to move or reparent, drop hints, smart guides, band selection, zones,
  the legend) in the view. Keys go to `controller.handleKey`; the editor is an
  `NSTextView` routing Return, Tab, ⇧Tab and Esc through the registry.
- The Mac's chrome is SwiftUI hosted in AppKit: about 40 views (the Format panel, the AI
  panel, find, filter, navigation, the palette, every sheet, Home, Settings), each showing
  itself from the controller's state. Apart from the outline, Gantt, minimap and the
  canvas's own views, they use AppKit in a handful of places: colours made through
  `NSColor`, an open panel, the general pasteboard, `NSWorkspace.open`, `NSImage` and
  font family lists.
- XCUITest on the iPad simulator has `typeKey(_:modifierFlags:)` (a hardware keyboard)
  and `performAccessibilityAudit`.
- No iPad is attached to this Mac (an iPhone 15 Pro Max is). Device numbers come from the
  iPad Pro 13-inch (M5) simulator until one is.
- Docker is available, so the iPad can be tested against MinIO and the relay server as
  M45 and M46 were.

## Plan

### `NexusTouch` (new package target; UIKit, compiled for iOS only)

- **`UIKitGraphics`**, the iOS text engine (`OpenNexusPlatformGraphics` by its
  Objective-C name, as on the Mac): UIKit's string drawing (TextKit), UIKit's dynamic
  system colours, `UIImage` decoding, `UIFontDescriptor` traits.
- **`TouchCanvasHost`**: `UIPasteboard`, the trait collection's appearance and contrast,
  the device's name, VoiceOver announcements. `CanvasHosts.platform()` makes it on iOS.
- **`TouchCanvasView`** (`UIView`) hosts the same `SceneRenderer` as `CanvasView`: the
  camera, culling, springs on a display link, reveal, fit, zoom, the drop indicator and
  the band, the editor and the anchored SwiftUI overlays (slash menu, ghosts, prompt bar,
  connect field).
- **Touch:**
  - tap selects, double-tap edits, drag moves or reparents with the Mac's drop hints;
  - long-press opens the context menu built from the registry (`UIContextMenuInteraction`);
  - pinch zooms around the fingers, two fingers pan, a one-finger drag on empty canvas
    draws a selection band;
  - Apple Pencil: Scribble writes into a topic (`UIIndirectScribbleInteraction`); hover
    shows the fold controls as the mouse does.
- **Keyboard:** `pressesBegan` maps `UIKey` to `KeyChord` and calls
  `controller.handleKey`, exactly as `keyDown` does on the Mac. Every registered command
  is also a `UIKeyCommand` (holding ⌘ lists them; the menu bar shows them), routed to the
  same call.
- **`TouchTextEditor`**: a `UITextView` over the topic, in the topic's text style, with
  Return, Tab, ⇧Tab, Esc, ⌘B, ⌘I and ⇧↩ routed as `NodeTextView` routes them.
- **Accessibility:** the M10 tree as `UIAccessibilityElement`s (topics in reading order,
  elements, the legend), with the same custom actions and rotors.

### Shared with the Mac

- **`CanvasPointer`** (NexusCanvas, both platforms): the drag state machine moves out of
  `CanvasView` (pan, band, topic, zone and legend drags, drop targets, guides and snapping,
  fold controls, decoration hits). The Mac's mouse and the iPad's touches drive it.
- **The SwiftUI chrome compiles for iOS:** the overlays, sheets, Format panel, AI panel,
  views and navigation, files, sharing, sync, collaboration, Home, the starter gallery and
  Settings. The AppKit calls go behind small helpers (`PlatformColor`, `PlatformOpen`,
  folder picking, the pasteboard through the controller's host). Mac code paths stay as
  they are.
- **`PlatformNetwork`** takes a provider the app installs. The Mac keeps the XPC service.

### The app (`OpenNexus iOS`, `App/iOS`)

- A SwiftUI app: `DocumentGroup` for `.nexus` packages and `.nexusjson` through the
  document browser (Files, iCloud Drive and other providers), the starter gallery for new
  documents, the browser's recents, Home's recent maps.
- **The document screen:** the canvas with the Mac's overlays; the Format panel as an
  inspector; Outline and Split; Focus, ZEN, filter, find, the navigation panel; the AI
  panel and ghosts; image to map with the VisionKit document camera; Gantt; Present on an
  external display or AirPlay with the presenter view on the iPad.
- **Network:** `NexusNet` runs in the app's process (the plan's rule for iOS). One file in
  the app adapts it to `ShareTransport` and `RoomConnector`; secrets are in the Keychain;
  every switch defaults off and every request goes to the same log.
- **Extensions (iOS targets of their own):** Quick Look preview and thumbnail, a Share
  extension that captures to the Inbox, the Inbox and Recent Maps widgets. App Intents and
  Core Spotlight indexing are in the app (iOS has no Spotlight importers).
- **Not on iOS:** the `nexus` CLI, the MCP server, Services, the global Quick Capture hot
  key, code links and Sparkle.
- A privacy manifest: no tracking, no collected data, and the required-reason APIs used.
- `App/tools/make_project.py` generates the iOS targets and their scheme.

### Tests

- **iOS unit tests** (`OpenNexusiOSTests`, hosted in the app, run on the iPad simulator):
  the 36 style × theme goldens rendered on iOS against the Mac's; iPad-against-Mac text
  parity over the corpus (M47a's known gap); `UIKey` chords; the touch canvas's gestures
  through their handlers; the host; the network adapter refusing hosts; the timing
  budgets.
- **iOS UI tests** (`OpenNexusiOSUITests`): F1 by hardware keyboard only and by touch
  only; VoiceOver's tree; Dynamic Type; `performAccessibilityAudit` on the canvas, Home and
  Settings.
- **Live, Mac and iPad** (`scripts/test-ipad.sh`, Docker): a Mac process and the iPad
  simulator sharing a folder library, an S3 library on MinIO and a live session on the
  relay; a share link made on the iPad opened in Chromium.
- **Mac:** `CanvasPointer` keeps every existing mouse test passing; `NetworkPrivacyTests`
  learn the iOS rule.

### Changed from the plan

- **The iPad has its own Xcode project** made by `make_ios_project.py` (D395), so the
  Mac's project file stays byte-identical.
- **`UIDocument` and Home rather than `DocumentGroup`** and the document browser (D388,
  D393): changes made elsewhere merge instead of reverting.
- **⌘, is iPadOS's;** Settings opens from the gear, and ⌘O is a menu-bar command (D405).
- **Settings on the iPad** leaves out the Mac's own rows (D407) and lays itself out for
  the iPad (D408); the Shortcuts pane has no Hyper key.
- **The hosted suites run serialized:** run in parallel, Swift Testing put the timing tests
  beside the windowed ones and roughly doubled their numbers.
- **The UI tests run touch first** (name order): once a test types on the hardware
  keyboard, the simulator keeps it attached and the on-screen keyboard's bar no longer
  shows.
- **The audit runs a still screenful at a time, contrast, then the other checks, then
  Dynamic Type,** with two exemptions and a re-measure (D408), rather than one
  `performAccessibilityAudit` per screen.
- **Text parity is a test** over every 27th (style, title) pair (8,317 topics), with a
  floor, rather than M47a's one-off run over all 74,875.

### Defects found

- **An open map lost an edit not yet saved when a synced folder replaced its file** (found by
  A5): the iPad merged the Mac's save, then `UIDocument`, once the writer was done, reverted
  to the file, dropping the iPad's topic and its undo, so the iPad's next save lacked it and
  the Mac's merge step failed. `TouchDocument` now merges on that revert too (D409), and a
  hosted test (`aChangeMadeElsewhereMergesWithAnUnsavedEdit`) repeats it without Docker.
  The live test had passed its own checks only because the revert landed after them; it now
  waits for it.
- **Return committed before the last letters arrived** ("Launch plan" saved as "Lau"):
  the keyboard inserts typed text after the key press (D403).
- **XCUITest's Return ("\r") never reaches the app** on iOS; the tests send "\n", the
  Return key's own press.
- **⌘, opened the Settings app** (iPadOS takes it, D405), and **⌘. arrived as Esc's
  characters** on the "." key, so it typed nothing and cancelled nothing (D406).
- **⌘Z had no route** on the iPad until the document's undo manager took it (D390).
- **The keyboard's shortcuts bar ran out of room** with a hardware keyboard's floating
  bar showing predictions; the two add buttons fold into "+" (D397).
- **A new topic's caret took 67–84 ms** while first responder swapped between canvas and
  editor (D394), and **75 ms again** while the parked editor switched predictions off and
  on at every commit; they now switch off only once typing pauses.
- **The brand lockup didn't draw:** the iPad's asset catalog lacked the brand images the
  shared views load by name.
- **Home clipped** its header search, chips and summaries (D404); **Settings overflowed**
  a sheet and showed the Mac's own rows (D407).
- **Settings' rows reported text that can't grow:** `ViewThatFits` and lazy stacks swap
  views as the text size changes (D408). **Each pane opened at the last pane's scroll
  position.** The panes' glyph tiles, two status colours, the counts bar and the key hints
  measured under 4.5:1.
- **The Watermark row's "Never" badge was white on the system green** (2.2:1); on the iPad
  it's on a darker green (D408).
- **The UI test's own audit was slow and unsure:** splitting `.all` (every bit) check by check
  made 63 passes a screenful, and auditing while the undo notice faded returned issues
  without an element, so the key-glyph re-measure couldn't reach them.
- **Everything the iPad drew offscreen was upside down** (found by A9, in Files' thumbnails):
  image export, `preview.png` and Quick Look, and slides, exported or in the presenter
  view. `SceneRenderer` flipped its root layer for AppKit on both platforms, and only the
  touch canvas undid it; now it flips only on the Mac (D410), and
  `GoldenTests.exportsAndSlidesAreUpright` reads an export and a slide with Vision. The
  goldens render through the touch canvas, so they hadn't shown it.
- **The Recent Maps widget never left its placeholder** (found by A9, on the home screen):
  WidgetKit refused to archive its timeline (`imageTooLarge`) because the thumbnail was the
  map's `preview.png` at full size, 1200 × 1098 pixels. Both platforms' widget extensions
  now load it at 400 pixels at most (`RecentMapsWidgetView.thumbnail`). Once it drew, **a
  tall map pushed the header and the titles out of the widget:** the grid gave its rows
  unbounded height, so a tile grew with its preview; the rows now share the height that's
  left. And **the App Group kept every thumbnail ever written** (60 files for one recent
  map); `WidgetSnapshot.write` removes those no map lists.
  `IntegrationTests.widgetThumbnailsAreSmallAndPruned` checks the size and the pruning; the
  view and the loader are the Mac's too.
- **Home listed the app's own Application Support folder as a location,** a raw sandbox
  path, because the Inbox lives there; Files can't show that folder, so Home leaves it out
  on the iPad (`IntegrationTests.theInboxFolderIsntALocation`).
- **A5's S3 step never read the bucket on the Mac's side:** the Mac half's test transport
  (`ShareLive.RealNetwork`) had no `exchange`, and `ShareTransport`'s default returns no
  bytes, so every object came back empty and was refused as "not encrypted". The step's
  check passed anyway, because a document's error leaves the library's status synced, so
  only the missing topic showed. The transport now reads, and both halves check what the
  sync log says (Added, Sent, Merged) with nothing flagged. The Mac app's transport and the
  iPad's both implement `exchange`.
- **`scripts/test-ipad.sh` stopped after its build step:** it greps each step's log for a test
  summary, and a build has none, which `set -o pipefail` made fatal.
- **The iPad's merge test hung** (`LiveTests.iPadMergesTheMacsSave`): it wrote the Mac's save
  through a file coordinator on the main thread while the open document, which answers the
  coordinator there, waited for it. A synced folder writes from another process; the test
  now writes from another thread, and waits for `UIDocument` to count the edit, which it
  does when the undo group closes.
- **The Appearance pane's live preview had no accessibility element** (found by the final UI
  run): the image of a sample map is decorative, and its topics' text, upside down until
  D410, now reads as text the audit can't reach. It's one labelled image on the iPad now,
  as the Editing pane's illustration is.
- **The Settings audit flagged text that had no element, on the last screenful of a pane**
  (Editing, Appearance, Files & Backup, Export, Privacy & Data, in two runs): the Dynamic
  Type check grows and shrinks the text, which at a pane's end moves the scroll position,
  and element detection in the same pass read the moved screen. A screenshot taken as the
  issues arrived showed the pane's title under the bar, though the audit had started at the
  pane's end. Dynamic Type is now a pass of its own, last. An earlier run had passed with
  the same code; whether the screen moves in time varies.
- **The Settings audit left out Sharing and Sync,** two of the iPad's 12 panes; it audits
  every pane now.
- **The Settings audit ran out of time on Shortcuts, and the simulator's `testmanagerd` took
  another core with each timeout** (the final UI runs; earlier, after nine hours of runs, it
  had reached about 17 cores and audits failed at random until the simulator restarted).
  Both causes were in the test's helper. Finding the scroll view took about 11 seconds on
  Shortcuts, which has over 700 elements, and the helper found it again at each step of
  every drag and for each screenshot it compared, so a screenful took about 2 minutes. And
  a contrast check that ran out of time on a screenful did so on every retry there
  (Shortcuts' eighth, in three runs), each try leaving a core busy. The helper now looks
  the scroll view up once, drags by the app's coordinates, compares screenshots of the
  screen, takes one snapshot per issue, and moves a screenful a tenth of the view before
  retrying a check there. A Shortcuts screenful takes about 35 seconds, and the final run
  had no timeouts.
- **The string catalog's copy phase** in `make_project.py` still named NexusCanvas's
  bundle after M47a moved the catalog to NexusScene; the committed project had it right.
- **Stale module files** in the iPad build's products shadowed fresh ones after targets
  changed; a clean build of the test bundle fixed it.
- **`CollabTests.presenceShowsRingsNameTagsAndEditingMarks` raced:** it waited for Ben to
  be listed, but he is announced with his presence, which follows; it failed under load and
  now waits for the announcement.

### Known gaps

- **No physical iPad:** every number is the simulator's, and the document camera (not in
  the Simulator), Pencil hover and Scribble ran only through their handlers.
- **Real iCloud Drive is untested;** a shared folder stands in for it (A5).
- **Presenting on an external display is neither automated nor checked** (A8): the scene,
  the canvas moving to it and the presenter view (D398) are built, and
  `thePanelsAndModesOpen` covers presenting on the iPad itself. The simulator lists an
  external screen (`simctl io enumerate`) but has no surface for it until it's turned on
  from a simulator window's I/O menu, which this run didn't use (Xcode 27 has no separate
  Simulator app here, and Device Hub wasn't granted).
