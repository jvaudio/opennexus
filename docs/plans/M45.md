# M45 · Bring-your-own sync

Phase 3 of `collaboration-and-reach.md`: maps follow the user across Macs through storage
they already own, and sync never silently loses an edit. Three ways: folders that iCloud
Drive, Dropbox, Google Drive or Syncthing already sync (OpenNexus merges their conflict
copies instead of picking one); an S3-compatible bucket that OpenNexus syncs a library to
itself, through `OpenNexusNet.xpc`, encrypted by default; and Git, where OpenNexus gives
the user's own `git` a merge driver and readable diffs.

Decisions #8 (S3 sync encrypted by default, with off available) and #9 (no in-app Git
until after M47) were confirmed on Oct 29, 2026 (D348–D349).

## Plan

### Merging (NexusCore)

- `DocumentMerge` reports each clash as data, `MergeClash` (where: a topic, a canvas's
  settings or a whole canvas; the canvas and topic ids; base, mine and theirs), beside the
  strings it already gives agents and the CLI, whose "app wins" behaviour is unchanged.
- `MergeResolution` applies a choice per clash: Mine, Theirs, or Both (theirs kept as a
  conflict-copy canvas, "<title> (theirs)"). Applying a resolution is one document
  commit, so one undo step.
- A merge without a base (two copies with no common version: an iCloud conflict version,
  a "conflicted copy" file) is two-way: what only one side has is kept, nothing is
  deleted, and every difference is a clash.

### Sync engine (`NexusSync`, a new platform-neutral module)

- **Library**: a folder of `.nexus` packages, connected to a bucket and prefix. Every
  document gets a stable `documentID` in `manifest.json` if it lacks one (added to the
  schema; the app already writes it for recovery snapshots).
- **Remote layout** under the prefix: `library.json` (each document's title and head,
  and tombstones), `docs/<id>/head.json` (revision, parent, device, time, and each package
  path's blob name), `docs/<id>/blobs/<name>` (every file once), and
  `docs/<id>/heads/<rev>.json` (history).
- **Encrypted by default** (D348): a random 32-byte library key; HKDF gives a sealing key
  and a naming key. Every object (blobs, heads, `library.json`) is a `Sealed` envelope
  (M44's format, D331); a blob's name is an HMAC of its content under the naming key, so
  equal files are stored once and names reveal nothing. The key lives in the Keychain and
  is shown as a recovery key (text and QR code) to set up another Mac. Unencrypted
  libraries store plain JSON and SHA-256 names.
- **Push**: upload the blobs the bucket lacks, write the history record, then replace
  `head.json` only if its ETag is unchanged (`If-Match`, or `If-None-Match: *` for a new
  document). If the head moved, pull, merge base · local · remote, write, push again.
  Test checks the provider honours conditional writes; if not, the engine writes, then
  reads back to verify.
- **Pull**: if the remote moved and nothing changed locally, fast-forward; otherwise the
  three-way merge. Clashes keep this Mac's side, are pushed, and are offered in Resolve
  Conflicts; nothing is lost because both sides are in the clash record and history.
- **Base copies**: per document, the last synced head and its files (by content hash) in
  the app container, so a merge always has its base. State is written only after the head
  write succeeds, so a crash between blob uploads and the head write loses nothing.
- **Deletes**: a tombstone in `library.json` with the date; other Macs move their copy to
  the Trash. The document's objects stay for 30 days (a setting), when any Mac purges
  them; Restore clears the tombstone.
- **History**: the head records, newest first; restoring one is one undo step.
- **When**: after a save (debounced), when a window becomes key, on an interval (a
  setting), at launch, and with Sync Now. The engine is an actor; hashing, sealing and
  merging run off the main thread, so typing isn't slowed.

### The network service

New `NetJob` actions for a bucket: get (with its ETag; a missing object isn't an error),
put (optionally `If-Match` or `If-None-Match: *`; a failed condition is reported, not
thrown), delete, list, and a sync Test that checks conditional writes. Replies can carry
bytes, so the XPC interface returns the reply and a body. Sync jobs' allow-list is the
libraries' hosts; every request is in the same log as sharing's.

### Folders other apps sync

- Opening a document finds its iCloud conflict versions (`NSFileVersion`) and sibling
  "conflicted copy" files (Dropbox, Google Drive, Syncthing, OneDrive patterns), and
  offers Merge Conflicting Copies…: a two-way merge into the open document with the
  Resolve Conflicts sheet, after which the versions are resolved and the copies go to the
  Trash.
- Opening an iCloud document that isn't downloaded yet starts the download and shows its
  progress.
- Reads and writes of packages go through `NSFileCoordinator`.

### Git (tier 1)

- `nexus merge-driver %O %A %B %P` merges canvas files, `manifest.json`, `theme.json`
  and `.nexusjson` files topic by topic with `DocumentMerge`, writes canonical JSON, and
  exits 1 only on a true clash, listing it (this side's version is written).
- `nexus git setup` writes the `.gitattributes` lines and the `git config` entries, and
  running it twice changes nothing.
- `nexus git textconv <file>` prints an outline, one topic per line with its parent, so
  `git diff` reads "+ Pricing (under Launch)".

### UI

- Settings › Sync (new pane): libraries (add a folder and its bucket, Test, Sync Now,
  Show Recovery Key…, Enter Recovery Key…, Reset Sync State, Remove), the interval, days
  to keep deleted documents, and the sync log. Privacy & Data › Network gains "Sync
  libraries" (off).
- Home lists libraries under Locations with their status, and each card shows synced,
  syncing, offline or conflict.
- Commands: Sync Now, Sync History…, Resolve Conflicts… (File menu).
- The Resolve Conflicts sheet: each clash with Mine, Theirs or Keep Both, and Apply.
- Remote changes arrive in an open document as one undo step: "Updated from sync · ⌘Z
  undoes".

### Tests

- `MergeClashTests`: clashes as data, each choice, Keep Both, one undo step, two-way.
- `NexusSyncTests` against an in-memory bucket that honours conditions: the property test
  (2–3 replicas, random edits and sync order, 50 seeds), clashes, encryption (no topic
  string in any object or name; the recovery key works, another key doesn't), what an
  edit uploads, a crash between blobs and head, deletes and Restore, history.
- `NexusNetTests`: the bucket operations against the stub (conditions, 404, list).
- `ConflictCopyTests`: iCloud versions and conflicted-copy files offered and merged
  (synthetic versions and files).
- `GitDriverTests`: in a temporary Git repository, two branches editing different topics
  merge cleanly; the same topic exits 1 with the clash; setup is idempotent; textconv.
- Live (`scripts/test-sync.sh`): the property test and the performance check against
  MinIO in Docker, through the real `NetService`.

### Built

- **NexusSync** (new, platform-neutral; NexusCore and NexusFormat only). The bucket
  protocol and an in-memory bucket; library keys, sealing and names, recovery keys; the
  records (library, heads, state); the folder protocol, with a coordinated disk folder that
  writes only over what it read; and `SyncEngine`, an actor: scan, per-document push, pull,
  fast-forward and three-way merge, retries when another Mac wins the head, overwrite
  detection for providers without conditions, deletes, Restore, purge, history, kept
  conflicts, the base cache and its garbage collection.
- **Merging.** `MergeClash` and choices in `DocumentMerge` (Mine, Theirs, Keep Both); a
  topic deleted on one side with a subtopic added on the other is now a clash instead of
  an invalid tree.
- **Network service.** Bucket get, conditional put, delete, list and the sync Test;
  replies carry a body over XPC.
- **App.** `SyncCenter` (libraries, Keychain, bookmarks, schedule, log, status);
  Settings › Sync (libraries with Test, Sync Now, Edit, Show and Enter Recovery Key… with a
  QR code, Deleted Documents…, Reset Sync State, Remove; the schedule; other ways to sync;
  the log) and "Sync libraries" in Privacy & Data; Resolve Conflicts, Sync History and the
  conflicting-copies sheet; File › Sync Now, Sync History…, Resolve Conflicts…, Merge
  Conflicting Copies…; "Updated from sync" in open documents; libraries and each card's
  status on Home; iCloud downloads from Home.
- **CLI.** `nexus git setup`, `nexus git textconv` and `nexus merge-driver`.
- **Tests and scripts.** `NexusSyncTests` (21, plus the soak), `BucketSyncTests` (3),
  `SyncTests` and `ConflictCopyTests` (13), `GitDriverTests` (5), `MergeClashTests` (8);
  `scripts/test-sync.sh` runs MinIO in Docker for the live tests.

### Changed from the plan

- **`library.json` lists documents and tombstones only** (D350); titles and heads are in
  each document's head, so Macs don't race over one file.
- **No separate `MergeResolution` type:** `DocumentMerge` takes the choices per clash.
- **Edits beat whole-document deletes, and password-protected documents sync whole**
  (D354, D355); the plan didn't say.
- **Sync writes only over what it read** (D356), added after finding a lost-save race.
- **Resolve Conflicts doesn't open by itself** (D363): the toast says how many conflicts
  kept your version and where to resolve them.
- **Enter Recovery Key… is part of the library editor** (Add and Edit), reached from the
  library's More menu, rather than a dialog of its own.
- **iCloud download shows a spinner, not a percentage** (D361).
- **A5's crash is simulated in process** (the head write fails, then an engine restarts
  from the saved state) rather than by killing a process.
- **Merge Conflicting Copies… is a command too**, beside the offer when a document opens.

### Defects found

- **A save during a sync could be lost** (D356). Sync read a package, spent a network round
  trip merging, then wrote over whatever was there; a save in between was overwritten on
  disk and then undone in the open document by its own merge from disk. Found while wiring
  the app. `aSaveDuringSyncIsNotOverwritten` fails without the fix.
- **A topic deleted on one Mac while another added a subtopic under it** left an orphan,
  so the whole canvas kept one side and lost the other's other edits. Found by the property
  test (7 of 50 seeds). It's a single clash now.
- **Downloaded files weren't kept as the next merge's base,** so later merges were two-way
  and reported clashes against damaged copies. Found by `theSameTopicOnTwoMacsIsOneClash`.
- **Without conditional writes, two Macs racing could overwrite a head unseen.** The first
  version of the test only synced one Mac at a time, so it passed; with concurrent syncs it
  failed, and the ancestry check (D353) fixed it (the test fails without it).
- **The sync log was saved once per line on the main actor**, a 55 ms stall in the latency
  test; it's saved once per sync now.

### Known gaps

- **Derived files aren't synced** (D352): a document another Mac changed has no Quick Look
  preview or viewer copy until it's opened and saved on this Mac.
- **The running app hasn't synced to a real bucket.** The engine and the network service
  were tested together against MinIO, and `SyncCenter` with an open document against an
  in-memory bucket, but not the app through its XPC service end to end.
- **Each sync asks for every document's head** (a conditional GET each, 304 when
  unchanged). That's fine for hundreds of documents on a 15-minute schedule; thousands
  would want a change feed.
- **Two-way merges** (conflicting copies, and the first sync after Reset Sync State) can't
  tell a topic each side added under the same parent from one topic edited twice, since
  topic ids count up per canvas: that's a clash, and Keep Both keeps both.
- **Google Drive's and OneDrive's conflict names** follow their documentation and weren't
  checked against the apps (D360).
- **Providers without conditional writes** can still race in the instant between a read
  back and another Mac's write; the next sync's ancestry check merges the overwritten
  revision back (D353), so nothing is lost, but it arrives a sync later.
