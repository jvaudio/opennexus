### One graph, many layouts

The tree stays the single source of truth. A diagram type only changes three things: how
the tree is laid out, how its edges are drawn, and what each node *is*. So:

- **Tree edges are the primary edges** of every technical type:
  - flowchart: a step to the next step;
  - DFD and threat model: a data flow;
  - architecture: a dependency.

  The artboards' keys already work this way. Tab is "next step", "downstream + flow" or
  "dependency"; Return is "parallel step", "sibling fed by same source" or "peer
  service". Relationships carry the extra edges (merges, return flows, cross-links), and
  in sequence diagrams they are the messages, in time order.
- **Convert never edits content.** It sets the canvas type and structure and fills in node
  types where the user confirmed them. Nodes, text, hierarchy, relationships and elements
  are untouched, which makes conversion lossless by construction. It is one undo step.

### Model (NexusCore)

- `Node.nodeType`: the technical type, an open enum. Examples: start, end, process,
  decision, io, document; entity, store; threat, mitigation, asset; the 32 icon types;
  participant.
  - It lives on the node rather than in a canvas-level map, so it survives duplicate,
    move and delete with no bookkeeping. This deviates from the README sketch; see the
    decisions.
  - With no explicit type, the type is *inferred* per diagram (root → start; text ending
    in "?" → decision; and so on).
- `Node.edgeLabel`: the label on the tree edge into a node ("Yes" / "No", "order
  details", "gRPC").
- `Node.lane`: the swimlane id.
- `Node.textFormat` (plain, math or code) and `Node.language`.
- `Canvas.diagram` (`DiagramData`):
  - `lanes` (`[Lane]`) and `ignoredRules`;
  - `parent` (the `{canvas, node}` a DFD level drills from);
  - `view` (`level` / `context`);
  - `colorByRisk` and `previousStructure`.

  Unknown keys round-trip.
- `DiagramCatalog`: each type's node types with caption, shape, look and icon; the
  inference rules; which types are hierarchy types and which ask for node types.
- `CanvasEditor.convert(to:nodeTypes:)` and `NodeTypeSuggester`, a heuristic classifier
  marked ✦. It is replaced by Foundation Models in M6.
- `DFDRules` (pure): returns violations, each with an id, rule, message, subject and
  fixes. The rules:
  1. A flow must touch a process.
  2. Every store is written.
  3. Every process has an input and an output.
  4. Every flow is labelled (warning).
  5. Levels are balanced.

  Fixes: insert process, reroute via a neighbouring process, ignore.
- `Stride`: STRIDE-per-element categories and rule-based suggestions; the threat table
  (ID, element, STRIDE, threat, risk, mitigation, status) with CSV and Markdown output.
- `Mermaid`: sequence and flowchart text, for "Copy as Mermaid".

### Layout (NexusLayout)

- **Structure order (artboard 18):** ⌥⌘1 Mind Map, 2 Logic, 3 Org, 4 Timeline,
  5 Fishbone, 6 Matrix, 7 Brace, 8 Tree Table, 9 Tree.
- **The new structures:**
  - **Org:** first level spreads horizontally on a bus. Below that, a parent whose
    children are all leaves stacks them in an indented column, wrapping to a new column
    past 6.
  - **Tree:** an indented tree growing down and right.
  - **Timeline:** events ride a horizontal axis; details hang beneath as indented stacks.
  - **Fishbone:** the head at the root; bones alternate above and below a spine; causes
    hang off each bone.
  - **Matrix:** a grid of cells (2 columns, or ⌈√n⌉ for more), items stacked inside,
    with a header bar.
  - **Brace:** logic placement with one curly brace per parent.
  - **Tree Table:** row headers, cell columns by depth, a header bar.
- **Mixed per branch:** any branch can carry an exotic structure. It is laid out in local
  coordinates, its bounding box is reserved in the parent's placement, and it is mirrored
  so it grows away from its parent.
- **Layout may widen a node** (header bars and table cells). The scene re-centres that
  node's content.
- **`GraphLayout`:** a layered (Sugiyama-lite) layout over tree edges plus relationships.
  - Steps: cycle breaking, longest-path ranks, ordering by tree order then barycentre
    sweeps (boundary members kept together), coordinate alignment by neighbour averaging.
  - Top-down for flowchart; left-to-right for DFD, threat model and architecture.
  - Swimlane adds lane bands as rows.
- **`SequenceLayout`:** participants in a row; messages at increasing y; lifelines;
  automatic activation bars (LIFO matching of calls and returns).

### Rendering (NexusCanvas)

- **Per-family connectors:** org bus, indented └, timeline axis, fishbone bones and causes.
- **Scene decor** (per-frame paths from live frames): brace, matrix cells, tree-table
  grid and colour bars, swimlane bands and hand-off labels, sequence lifelines and
  activation bars.
- **Node types draw as style layers under the node's own style**, plus:
  - a caption outside the node (PROCESS, EXTERNAL ENTITY, START);
  - a kicker inside (1.0, D1, SERVICE);
  - an icon in the lead slot (the 32-icon set).
- **Technical tree edges draw as relationships:** elbow or straight, a filled arrow and a
  plain label, with draw-on, labels and hit testing. Selecting one edits the child's
  `edgeLabel`.
- **Technical types except flowchart draw the root as the diagram's title**, not a node.
- **DFD:**
  - Process numbering (1.0, 2.0) and store numbering (D1, D2).
  - Violating flows draw red and dashed, with a "!" badge and a shake when they first
    appear.
  - A violation card offers the fixes; ↩ applies the first.
  - A side panel holds Levels (Context, Level 1, drilled processes; ⌘. drills in) and
    Rule checks.
- **Threat model:**
  - Threat, mitigation and asset cards.
  - Colour by risk.
  - A STRIDE tab in the Format panel: six categories per element with risk, suggestions
    (✦) and Owner / Data class / Protocol.
  - The threat table panel, with filter, Export CSV and Copy as Markdown.
  - "✦ Suggest STRIDE threats" with accept all (⌃⇧↩).
- **Architecture:**
  - The icon library (⇧⌘Y): search and categories; ↩ inserts a child; drag to place.
  - Protocol labels default from the target type, with label suggestions while editing.
- **Sequence:**
  - Messages and returns, numbering, activation bars.
  - Tab: message to the next participant; ↩: next message; ⌥↩: return message.
  - Copy as Mermaid.
- **Flowchart:**
  - Tab from a decision opens the edge label pre-filled "Yes", then "No".
  - Swimlane: ⌥↑ / ⌥↓ moves a step between lanes; "HAND-OFF" marks edges that cross a
    lane.
- **Convert (⌥⌘T):**
  - Eight featured tiles with wireframe previews rendered from *this* canvas, plus chips
    for the other types; filter, arrows, ↩, Esc.
  - Technical types go on to "Confirm node types" for first-level branches, with ✦
    suggestions.
  - A 600 ms morph: nodes glide; edges fade and redraw; badges fade in.
  - ⌘Z returns in one step.
- **Slash menu (`/`):**
  - In Select mode, or as the first character of an empty topic.
  - It lists the diagram's node types and the icon slugs (/db, /queue …), content (/math,
    /code, /todo, /note, /link, /image, /audio, /sticker, /label) and elements
    (/boundary, /summary, /callout, /zone).
  - It filters as you type.
- **`/math`:** a LaTeX subset (Greek, sub- and superscripts, \\sum, \\frac, \\sqrt,
  \\cdot, operators) rendered in the node.
- **`/code`:** a monospace dark block with keyword, string, number and comment
  highlighting.

### Tests

- **Layout:** each structure is free of overlaps and keeps the artboard's invariants.
  - Timeline events share the axis; fishbone bones alternate.
  - Matrix cells form a grid; tree-table rows don't overlap.
  - Org leaves stack.
  - Mixed branches don't collide with their siblings.
- **Graph layout:** edges point forward in rank (except broken cycles), no overlaps, and
  the result is deterministic.
- **Sequence layout:** messages are ordered in y; activation bars match calls and returns.
- **Convert:**
  - Property test: random canvases through map → flowchart → DFD → map keep nodes,
    text, hierarchy, relationships and elements identical.
  - map → flowchart → map is exactly equal.
  - Every convert is one undo step.
- **DFD rules:** each rule has positive and negative cases, plus the fixes. The canvas
  shows the violation badge and the shake.
- **STRIDE:** suggestions per element type; table rows; CSV and Markdown escaping.
- **Mermaid:** golden text for sequence and flowchart.
- **Slash menu:** filtering, keyboard flow, `/db` sets the type; the math and code
  renderers.
- **Snapshots:** structures and each technical canvas, compared against artboards 18–23
  and 10.

Defects found during M4 review and fixed:
- Node decorations weren't passed through to the scene, so captions, kickers and D1 labels were missing.
- Terminal and step text was dim against its fill.
- In technical canvases, relationships used the mind-map amber pill style instead of neutral flows.
- Plain labels were struck through by their line. They now sit on a canvas-coloured chip.
- The process input/output rule counted threat links as data flows.
- Org sub-topics drew as bordered main topics.
- DFD numbering followed depth-first order instead of flow distance.
- Threat-model overlays covered one another.
