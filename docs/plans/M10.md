# M10 · Hardening

## Plan

**Goal (README §11, §12 quality bars, §13 testing strategy):**
- The VoiceOver canvas tree, read as "Topic, level 2, 3 children, collapsed".
- Dynamic Type for the chrome.
- Full keyboard reachability.
- Performance passes against the 5k-node, 120 fps target.
- Localisation scaffolding.
- Crash-free fuzzing of the file loader.

**Accept when:**
- Every row in §12 is met and recorded.
- An accessibility audit reports no issues.

### VoiceOver canvas tree

- **The tree:** the canvas exposes its topics as nested accessibility elements, a tree
  under the central topic, with floating topics alongside.
  - **Labels:** each element's label comes from the shared spoken description. It
    includes the role, "level N of M", the child count, collapsed, the note, branch
    colour and edges, per Settings › Accessibility.
  - **Geometry and focus:** each element's frame is the topic's on-screen frame, so the
    VoiceOver cursor and the canvas agree. Selecting a topic moves VoiceOver focus to
    it.
  - **Actions:** press (select), "Edit", "Add child", "Fold or unfold". Each one goes
    through the command registry, so it's undoable.
- **Rotors:** Topics, Edges, Boundaries, Notes, AI suggestions and Connect targets.
  These are the categories the Settings preview names.
- **Performance:** elements are built only when VoiceOver asks, and cached until the
  scene changes. A 5k map isn't slowed for everyone else.
- **Connect mode:** it already announces its targets. Each candidate's element also
  carries its hint letter.

### Dynamic Type for the chrome

- **`Font.chrome(size:weight:design:)`** replaces fixed system fonts in the SwiftUI
  chrome: Settings, Home, onboarding, sheets, popovers, overlays, the status bar and
  Quick Capture. It scales by `ChromeText.scale`, an observed value, so open windows
  re-render when it changes.
- **The scale:** Settings › Accessibility › Follow system text size takes it from the
  system's preferred body size, rechecked whenever the app becomes active. When the
  setting is off, the scale is 1. Canvas text is unaffected; that has its own minimum
  text setting.
- **Checks:** snapshot checks at 1.3× and 1.6× for clipping.

### Full keyboard reachability

- **Every command is reachable:** each command in the registry has a key or appears in
  the palette. A test checks that no menu item, toolbar button or overlay button lacks
  a command or a key path.
- **Panel focus:** F6 and ⇧F6 move focus between window regions: canvas, tab bar,
  inspector, AI panel, outline, then back.
- **Settings › Accessibility › Full keyboard access to panels:** makes every chrome
  control focusable and reachable with Tab, even when the system's Keyboard navigation
  setting is off, with a visible focus ring.
- **Popovers and sheets:** each opens with focus on its first field and closes with
  Esc.

### Performance (README §12)

- **`Benchmarks/`:** the generator for the 1k and 5k maps (`nexus` can write them), plus
  a README.
- **Tests that measure:**
  - Key to caret: under 16 ms (existing).
  - 1k reflow: under 50 ms (existing).
  - 5k pan and zoom: the frame work under 8.3 ms per step (120 fps), with offscreen
    topics culled.
  - Open a 1k document (read, validate, lay out, first scene): under 1 s.
  - First AI ghost: under 1.5 s with Apple Intelligence (env-gated, since it depends
    on the model). The scripted engine's path covers the app's own overhead.
  - Network traffic: none. Static check: no networking APIs in any target, and no
    network entitlement.
  - Contrast: AA for every theme, AAA for High Contrast (existing).
- **A profiling pass on the 5k map:** fix whatever dominates.

### Localisation scaffolding

- **`defaultLocalization: "en"`,** with a String Catalog (`Localizable.xcstrings`) in
  NexusCanvas and NexusKeys.
- **`Loc(_:)`:** the user-facing titles in the registry (commands, categories, scopes)
  and the Settings schema (panes, sections, rows, options) go through it, from one
  catalog.
- **A coverage test:** every command and Settings string has a catalog entry. A
  generator keeps the catalog in sync.
- **Pseudo-localisation:** the `-NexusPseudoLanguage` launch argument, or the test
  environment, lengthens and accents every catalog string. Snapshot checks catch
  truncation.

### Fuzzing the file loader

- **Package reads:** mutated manifests and canvases (bit flips, truncation, type swaps,
  huge numbers, deep nesting, duplicate ids, child cycles, dangling references,
  self-parenting, empty and oversized strings). Each read either throws or yields a
  document that validates and lays out.
- **Never crash or hang:** a cycle must not recurse forever.
- **Other loaders:** `DocumentJSON.parse`, `Zip.read`, `PackageCrypto.decrypt`, the
  snapshot reader and `CanonicalJSON` get the same treatment.
- **Seeded and repeatable,** with thousands of cases per run.

### Accessibility audit

- **An in-process audit:** walk the accessibility tree of every key screen (Settings
  panes, Home, Welcome, role picker, tour, the canvas with overlays, the export sheet,
  Quick Capture, the Share sheet). Every actionable element must have a label, a role
  and a frame inside its window.
- **The system audit:** an XCUITest target runs `performAccessibilityAudit()` on the app.
  It also includes smoke tests of F1 (20 topics keyboard-only) and F5 (the tutorial).
  macOS may ask once for permission to let the test runner control the app.
- **Reduce Motion and Reduce Transparency:** checked on every overlay that animates
  or is translucent.

### Built

- **Fuzzing the file loader** (`LoaderFuzzTests`): 1,500 byte-damage cases, 2,500 structural JSON mutations, targeted cycles, second parents, orphans and pure cycles, and 1,200 cases each against zip, JSON documents, sealed packages and canonical JSON. Every case either throws, or opens as a document that validates, walks, lays out and renders.
- **Repair on load** (`Canvas.repair()`): damaged files open without losing topics. Repairs are reported in a toast and by `nexus validate`; saving keeps the fix.
- **The VoiceOver canvas tree** (`CanvasAccessibility`):
  - Elements are created lazily and reused per topic; frames are live (they follow the camera without a rebuild).
  - Labels come from the shared spoken description (role, level, children, collapsed, node type, branch colour, note, to-do, edges).
  - Actions: press, Edit, Add child, Add sibling, Connect from here, Fold or Unfold; each is one undo step.
  - AI suggestions sit under their topic, and pressing one accepts it.
  - Rotors: Topics, Notes, Edges, Boundaries, AI suggestions, Connect targets.
  - Hit-testing works under the VoiceOver cursor, and focus follows the selection while an assistive app runs.
- **Dynamic Type for the chrome:**
  - `Font.chrome` replaces 439 fixed sizes, scaled by `ChromeText` (follow system text size, 0.85×–1.6×).
  - System controls step to large and extra large control sizes, and sidebars widen.
  - A Settings row moves its control under the title when it doesn't fit.
- **Keyboard:**
  - F6 and ⇧F6 move focus between the canvas tabs, the canvas or outline, the AI panel and the Format panel, and announce the region.
  - Settings › Full keyboard access to panels makes Tab reach every control in OpenNexus.
  - A test proves every command has a key, a menu item or a palette row.
- **Localisation scaffolding:**
  - One String Catalog (988 strings): data-driven strings (commands, Settings rows and options) are looked up through `Loc.t`, and literal UI strings are scanned from the sources.
  - The app carries the compiled strings in its main bundle, so SwiftUI literals resolve too.
  - A coverage test fails on any missing string, and a generator keeps the catalog in sync (`NEXUS_WRITE_CATALOG=1 swift test --filter writeStringCatalog`).
  - A pseudo-language (`-NexusPseudoLanguage YES`) accents strings and lengthens them by about 40%.
  - **Text with values** (added after M10): chrome text with values in it goes through `Loc.f("Slide %lld of %lld", …)`, and counts through `Loc.n("%lld topic", "%lld topics", n)`. The generator writes the English plural variants (94 format keys, 31 with plurals), and a test fails on an interpolated SwiftUI literal or a hand-written `n == 1 ? "topic" : "topics"`. This replaces "1 topics" everywhere it appeared.
- **Performance work:**
  - Viewport culling.
  - The minimap's topics cached as a bitmap per scene.
  - The dot grid drawn once and shifted by its phase while panning, and hidden below 12 pt spacing.
  - Status-bar counts cached per document revision.
- **`Benchmarks/`:** a README and a generator for the 1k and 5k maps (`NEXUS_WRITE_BENCHMARKS=1 swift test --filter writeBenchmarkMaps`).

### Defects found during M10 and fixed

- **Crash:** a number too large for `Int` in a file (`paletteShift`, `schemaVersion`, text-mark ranges) trapped on conversion. It's now a decoding error. A huge PBKDF2 iteration count could also have made opening a file hang; it's now bounded.
- **Crash or hang on damaged structure:** child cycles, a topic listing itself, second parents and unreachable topics made tree walks recurse forever. Such files are now repaired on load.
- **Crash on deep nesting:** a 3,000-level chain overflowed the stack in `Canvas.walk`. The walk is now iterative, nesting is capped at 256 levels (deeper branches move to floating topics on load), and the editor refuses to nest past the cap.
- **Panning a 5k map took 37 ms per step.** The minimap redrew all topics, and the grid redrew every dot, on every step.
- **Zooming took 80 ms per step.** The status bar recounted 5,000 topics on every zoom change, and the grid drew anti-aliased ellipses.
- **Add Topic ＋ buttons drifted.** They stayed put when the camera moved (M8). They now follow the camera.
- **Recomputed on every edit:** VoiceOver's value was rebuilt after every scene update. It's now computed when read.

Found by the UI tests (2026-10-15) and fixed:
- **One Return counted twice.** Pressing Return on Welcome also pressed the role picker's default button, because the content was swapped while the key event was still being handled. The picker's Return then reached the new map and committed its central topic. Onboarding transitions now wait for the next run-loop turn.
- **Lesson 1 accepted the placeholder.** It completed when the central topic was committed unnamed, because the empty commit brings back "Central Topic". It now needs a name the user typed.
- **The tour bar wasn't accessible.** Its "Lesson N of 6" label sat on shapes, which make no accessibility element. The bar is now a "Tutorial" group with a real lesson element.
- **The canvas read as dimmed.** It reported itself disabled to accessibility clients.
- **Settings sidebar items read with their letter badge** ("G, General"). They're now labelled by pane name, with stable identifiers.
- **The F1 UI test assumed one undo removes a topic.** Naming a topic is its own undo step, so ⌘Z reverts the name first.

### Accessibility audit (2026-10-15)

Accessibility Inspector's audit found 3 warnings on Home and 15 on a document window
with the Format panel open. Inspector couldn't be pointed at a new build from
automation (its target chooser is a pop-up menu), so the rerun used
`App/tools/axaudit.swift`. It runs the same checks (no description, unknown role,
action missing) as a real assistive client, so SwiftUI builds its whole tree.

**Result: 0 issues on every screen.**
- Welcome, the role picker and tour lesson 1.
- Home.
- A document window with the Format panel open, the Export sheet, the Command Palette, Quick Jump, the Search tab and the Icon Library.
- All ten Settings panes.

Fixed:
- **Tap gestures with no button semantics:** cards, chips and swatches (16 sites). They now go through `accessibleTap`, which adds the button trait and a default action.
- **Unlabelled controls:**
  - Colour wells (11 sites).
  - Sliders: sibling gap, level gap, boundary tint and JPEG quality.
  - The node text editor.
- **Grids and scroll areas without names:**
  - 19 lazy grids.
  - Every SwiftUI scroll view (21).
  - Each canvas overlay host.
  - The Format panel and the tab bar.
  - The Home, Welcome, Settings and Quick Capture windows. Welcome and Quick Capture now have window titles.
- **Menus read as two elements:** each menu read once by its title and once by its label. The label is now hidden and the menu itself carries the name (`LabeledMenu`).
- **Unknown roles:**
  - The mode pill and the tour's lesson dots are now static text.
  - A multi-line Settings text field was merged into its row; it now stays a field of its own.
- **A link with no action:** the sample server address on the AI pane was auto-linked. It's now plain text.
- **Low contrast:** the Format panel footnote measured 1.01:1, because vibrancy changed `.secondary`. It now uses an explicit system colour.
- **Wrong plural:** the status bar read "1 topics".
