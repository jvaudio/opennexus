# M23 · Real Xmind files

## Plan

**Goal (Xmind parity, verification):** check the Xmind importer and both exporters against
two real Xmind 26 maps supplied by the user, fix whatever doesn't match, and produce
edited copies to open in Xmind.

The files stay where the user keeps them. Nothing from them is copied into the
repository; tests use made-up stand-ins with the same structure.

**Accept when:**
- **A1 · Content:** every topic imports at its path, in order, with its fold state and
  markers, checked against Xmind's JSON read directly (not through the importer).
- **A2 · Look:** an imported map looks like Xmind's own thumbnail of it: background,
  branch colours, topic fills and borders, fonts and text colour.
- **A3 · Round trip:** an export to `.xmind` and XMind 8, imported again, keeps the
  outline, and the `.xmind` export also keeps the look.
- **A4 · Edited copies:** each map, with a test branch using every element the export
  writes, is exported to `.xmind` and XMind 8 for opening in Xmind, and reads back as
  edited.

### The two files

| | Entegral Application Security | Security Engineering Roadmap FY26 |
| --- | --- | --- |
| Written by | Xmind 26.01 (Vana), data structure 2, layout engine 4 | Xmind 24.01 beta, layout engine 3 |
| Shape | 1 sheet, 69 topics, 5 levels, logic chart (right) | 1 sheet, 60 topics, 7 levels, horizontal timeline |
| Uses | folded branches, a full theme, a sheet style (dark background) | 29 topic styles (border widths, a shape), progress markers (done, ½, ⅛, ⅝), a Pitch extension, `zones: []`, `arrangeableLayerOrder`, `compactLayoutModeLevel` |
| Archive | Xmind Cloud download: zip comment holds cloud metadata | the same |

Neither file has tasks, comments, a legend, relationships, boundaries, summaries or
zones, so those importers are still unchecked against real Xmind files (see Known gaps).

### Approach

- **Inventory:** a key-by-key walk of each `content.json` lists what Xmind wrote.
- **Content check:** each topic's title, children order, fold state, markers, border
  width and shape, compared with the imported canvas.
- **Look check:** our PNG render beside the file's own `Thumbnails/thumbnail.png`.
- **Harness:** `XmindRealFileTests`, enabled only by `NEXUS_XMIND_REAL`, so the normal
  suite never touches the user's files.

### Found and fixed

- **The background came from the wrong place.** Xmind paints the sheet's own
  `style.svg:fill` over the theme's map fill. Entegral's sheet is `#111111FF` on a
  `#F6F5F5` theme, so we showed a light map that Xmind shows dark (D213).
- **Xmind's branch colours were dropped.** `multi-line-colors` became our default
  palette. They now travel with the canvas (D210).
- **Topic classes were dropped.** Central, main, sub and floating topic styles (fill,
  border, shape, font size and weight, alignment) became nothing. They're now role styles
  on the canvas (D211), read with Xmind's meanings (D212).
- **`roundedfold`**, Xmind 2026's line from the central topic, wasn't known. It reads as
  curved, and the central topic's line class now decides the canvas's line shape.
- **Found by the round trip:**
  - The writer stamped the canvas font on every topic class, overwriting a class's own
    font (Entegral's floating topics use Montserrat).
  - A topic fill in the branch colour was dropped, because it isn't a hex value. It's now
    Xmind's colourless solid fill, which means the same thing.
  - A canvas-coloured fill was dropped too. It's now Xmind's "no fill".
- **Round trips of another app's theme:** a theme we wrote is tagged `opennexus.<id>`
  and reimports as just that theme. A canvas carrying imported colours or roles is now
  written untagged, so they come back (D211).

### Built

- **`CanvasStyle.colors`** (hex list) with palette `"canvas"`, and **`CanvasStyle.roles`**
  (`root`, `main`, `sub`, `floating` → `TopicStyle`). Both are optional; schema updated in
  both copies; files without them are unchanged.
- **`StyleEnvironment`:** palette `"canvas"` resolves to `colors`; `roles` layer over the
  theme and node style, under level, quick and topic styles.
- **`XmindStyle`:** `canvasStyle(_:sheetStyle:report:)`, `roleStyle(_:role:)`; the writer
  merges roles into each topic class, keeps a role's own font, and writes branch and
  canvas fills as Xmind's colourless solid fill and no fill.
- **Format panel › Colour theme:** "This map's colours" appears when a canvas has its own.
- **Import report:** "Xmind theme's boundary, summary and relationship styles (OpenNexus's
  are used)" replaces "Xmind theme (its background is kept; OpenNexus's theme is used)".

### Known gaps, carried forward

- **The horizontal timeline lays out differently.** Xmind alternates each period's
  branches above and below the axis, each growing to the right as a logic chart. Ours
  hangs every period's branch below the axis as an indented list (our own design). The
  content is the same; changing it is a layout decision.
- **Progress markers in eighths** (`task-oct`, `task-3oct`, `task-5oct`, `task-7oct`) round
  to our quarters (⅛ → 25 %, ⅝ → 50 %), so a re-export changes them. Our markers are fixed
  glyphs with no eighths; the importer has rounded them this way since it was written.
- **Not imported:**
  - The theme's boundary, summary and relationship classes.
  - Theme topic classes on XMind 8 files.
  - Xmind's `importantTopic`, `minorTopic` and `expiredTopic` classes.
- **Not kept:** the Pitch extension (`org.xmind.ui.ice-cream-pancake`: slide appearance
  and aspect ratio), `compactLayoutModeLevel`, `arrangeableLayerOrder` and
  `topicOverlapping`. They're reported or ignored on import and not written back.
- **Zones:** the roadmap confirms the sheet key `zones` (an array), but a zone object
  itself is still unseen, so Xmind's zones still don't import.
- **Tasks, comments, legends, relationships, boundaries, summaries:** these importers are
  still unchecked against Xmind-made files, because neither sample has any. A map made in
  Xmind with them is the next check.
- **Fonts:** Xmind's NeverMind isn't on macOS; it falls back to the system font, as Xmind
  does elsewhere.
