# M20 · Zone gaps

## Plan

**Goal (closing gaps from M13 and M16):** export every zone at once, and copy, cut, paste
and duplicate zones.

**Accept when:**
- The export sheet's zone scope offers "Each zone as its own file", writing one PNG, JPEG,
  SVG or PDF per zone into a chosen folder, named after each zone's title (unique and
  safe for file names). PDF also offers one file with a page per zone.
- A palette command opens it; `nexus export` gets it if `CLIFormat` already has a zone
  option.
- Copying a selected zone takes the zone, its members' branches and the relationships
  whose ends are inside the copy, zone ends included (remapped to the new zone).
- Pasting into the same canvas, another canvas or another document places the zone at the
  paste point. A relationship to something outside the copy is kept in the same canvas
  and dropped otherwise, as `graft` does for dependencies (M11).
- Duplicate Zone is a command; cut is copy-then-delete as one undo step.
- The existing clipboard format, with zone data added compatibly.
- The end remap handles end kinds generically, since M18 is adding boundary, summary and
  callout ends to `RelationshipEnd` in parallel.

### Export each zone

- **`ExportState.zones`:** `.one` (this zone), `.each` (a file per zone) or `.pages` (PDF
  only: one file, a page per zone). It's never remembered, like the zone scope. Switching
  from PDF to another format turns `.pages` into `.each`.
- **The sheet:** with Zone scope, a Zones picker replaces PDF's Pages picker. The size line
  reads "5 files" or "5 pages".
- **Each file** (`CanvasController.zoneFiles`) is the zone-scoped export of that zone, so
  it's identical to exporting the zone alone. The folder is chosen with the same save
  path as Export Split by Main Branch (`onSaveFolder`).
- **File names** (`ImageExporter.fileNames`): the zone's title, with `/`, `\`, `:` and
  control characters turned into `-`, no leading dots or surrounding spaces, at most 100
  characters, "Zone" when empty, and " 2", " 3" for repeats ignoring case.
- **A page per zone:** `PrintLayout.pages` draws one page per set of options, each its
  content's size; `singlePage` is now one page of it. Saved as "Map – Zones.pdf".
- **Export Each Zone…** (`file.exportZones`, ⌘K and the File menu): the sheet on the last
  visual format, Zone scope, a file per zone. Hidden when the canvas has no zones.
- **CLI:** `CLIFormat` has no zone option (no scope at all), so `nexus export` is unchanged
  (D198).

### Copy, cut, paste and duplicate

- **`Canvas.zoneFragment(_:)`** (NexusCore/Clipboard.swift): a fragment like `fragment(_:)`
  with `zones` (the zone), `floating` (its members), the members' branches at their
  positions, the boundaries and summaries inside them, and every relationship that touches
  the copy, ends outside it included. The placeholder root lists the members, so an older
  build pastes the branches as topics.
- **`CanvasEditor.pasteZones(_:by:_:sameCanvas:)`** and **`pasteZones(_:at:sameCanvas:)`**:
  fresh zone, topic, relationship, boundary and summary ids; members stay floating, moved
  with the zone. A relationship end is remapped by `remap`: a copied topic or zone moves
  to its copy, any other end survives only when `sameCanvas` and it's still on the canvas.
  Dependencies follow the same rule.
- **`graft` shares the code:** `insertCopies` (nodes, links, dependencies) and
  `copyElements` (relationships, boundaries, summaries). Its behaviour is unchanged.
- **Generic ends:** `remap` switches over `RelationshipEnd` with `.topic`, `.zone` and an
  `@unknown default` that looks the end up by its `kind` and id among the copied elements
  (boundaries and summaries are recorded by kind already). A new case compiles with a
  warning and is either remapped or kept in place; nothing breaks.
- **The canvas:**
  - ⌘C, ⌘X and ⌘V (and Edit › Copy, Cut, Paste) act on a selected zone. Paste puts the
    zone's top-left corner where a new floating topic would go and selects it.
  - "Same canvas" means the same open document too: the pasteboard also carries
    `org.opennexus.fragment.source`, `DocumentStore.sessionID` plus the canvas id
    (D197).
  - Cut removes the zone and its contents in one step (`removeZoneWithContents`).
  - Duplicate Zone (`element.duplicateZone`): ⌘K (shown when a zone is selected or holds
    the selected topic), ⌘D on a selected zone, and a Duplicate button in the Format
    panel's zone section. The copy goes 40 pt to the right of the original.
  - Undo of a paste clears the selection of a zone that no longer exists.

### Known gaps

- **`nexus export` and the MCP `export` tool can't export a zone** (D198). They have no
  scope option of any kind; adding branch, selection and zone scopes is its own change.
- **Only one zone at a time is copied from the canvas,** since a selected element is a
  single zone. The model (`zoneFragment` and `pasteZones`) already takes several.
- **Topic copy and paste still decide "same canvas" by canvas id alone** (`graft`), so a
  dependency can survive a paste into another document whose canvas and topic ids
  happen to match. Zone paste uses the session-and-canvas source (D197); topic paste could
  use it too.
- **Callouts on a zone's topics aren't copied,** as with topic copy (`fragment` never
  carried them).
- **The zone's right-click menu** has no Copy, Cut or Duplicate yet; the right-click work
  (M17) owns that menu.
