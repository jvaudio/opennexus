# M11 · Task planning

## Plan

**Goal (parity with Xmind 2026's tasks and Gantt chart):**
- Task fields on a topic: start, due, owner, progress and priority.
- Dependencies between tasks (finish-to-start and the other three kinds, with a lag).
- A Gantt view of the same canvas, which skips non-working days.
- Export of the Gantt as PNG, JPEG and PDF, and of the tasks as CSV and ICS.
- Importing Xmind's task info instead of skipping it.

**Accept when:**
- **A1 · File format:** a topic's task fields and dependencies round-trip byte-identically.
  Older files open unchanged, and a file with no task fields is written exactly as before.
- **A2 · Editing:** every task field can be set from the keyboard on the canvas and in the
  Gantt. Each edit is one undo step.
- **A3 · Dependencies:** they survive copy, paste, duplicate, delete and repair, and a
  cycle can't be created.
- **A4 · Gantt view:** ⌘4 shows the canvas as a Gantt chart, and selection is shared with
  the canvas and outline. Bars skip non-working days. Moving a task moves the tasks that
  depend on it. Every action has a key.
- **A5 · Export:** the Gantt exports as PNG, JPEG and PDF, and the tasks as CSV and ICS.
  ICS output follows RFC 5545 and opens in Calendar.
- **A6 · Xmind import:** Xmind's task data (Zen and XMind 8) becomes task fields and
  dependencies, and the import report counts the tasks.
- **A7 · Quality bars:** strings are localised, the accessibility audit is clean, there
  are no network APIs, and a 1,000-task Gantt lays out in under 50 ms.

### Data model (NexusCore)

**`Todo` grows optional fields.** Each is omitted when unset (D3), so `{"done": false}` is
still a plain to-do and today's files stay byte-identical:

```json
"todo": {
  "done": false,
  "start": "2026-11-02",
  "due": "2026-11-06",
  "owner": "Ana",
  "progress": 40,
  "after": [{ "task": "n7" }, { "task": "n9", "type": "SS", "lag": 2 }]
}
```

- **`start` and `due` are calendar dates (`yyyy-MM-dd`)** with no time and no time zone.
  `due` is inclusive. A task with only `due` is a milestone. A task with only `start`
  lasts one day.
- **`owner`** is free text. Xmind's several assignees are joined with ", ".
- **`progress`** is a whole percentage (0–100), omitted at 0. The effective progress is:
  - 100 if `done`;
  - otherwise `progress`;
  - otherwise the topic's progress marker (`progress-25`… from D91);
  - otherwise 0.

  Setting progress to 100 checks the to-do. Unchecking it keeps the stored percentage.
- **Priority stays the existing `priority-N` marker** (`Node.priority`, ⌃1…9). The task
  editor sets that marker, so there aren't two priorities.
- **`after` lists the successor's dependencies:** each names the predecessor topic, a
  `type` (`FS` by default and omitted, or `SS`, `FF`, `SF`) and a `lag` in working days
  (0 by default and omitted). It's stored on the successor, as Xmind does. A dependency
  stays within its canvas.
- **Unknown keys inside `todo` and inside each dependency still round-trip** through
  `extra` (D4).
- **Toggling a to-do keeps every other field.** `TreeOperations.toggleMarker` currently
  rebuilds `Todo(done:)` and would drop them; that's fixed.
- **A canvas's work calendar** is `canvas.schedule`, written only when it isn't the
  default:

  ```json
  "schedule": { "workdays": [1, 2, 3, 4, 5], "holidays": ["2026-12-25"], "skipNonWorking": true }
  ```

  The default is Monday to Friday, no holidays, with non-working days skipped. Weekdays
  are ISO numbers (1 is Monday).
- **Schema:** `nexus.schema.json` and its bundled copy describe the new fields and
  `schedule`, with an `x-since: "M11"` note on each.

**Keeping dependencies consistent:**
- **Delete:** deleting a topic removes the dependencies that point at it, in the same
  patch. "Delete, keep children" does the same.
- **Copy and paste (`graft`):** a dependency inside the copied branch is remapped to the
  new ids. One that points outside the branch is kept when pasting into the same canvas
  (Duplicate Branch) and dropped otherwise.
- **Merge as canvases:** ids within a canvas don't change, so dependencies need no
  rewriting.
- **`repair()`:** drops dependencies on missing topics, on the topic itself, or repeated.
  Each kind of fix is listed (D126).
- **`validate()`:** reports a dependency cycle. Loading keeps the cycle so nothing is
  lost; the Gantt marks it, and the editor refuses to add a dependency that would close
  one.

**Scheduling (`Schedule.swift`, pure and headless):**
- **`WorkCalendar`:** checks whether a day is a working day, adds n working days, and
  counts working days between two dates. With skipping off, every day is a working day.
- **`TaskSchedule.build(canvas)`:** finds every task's effective start and finish, the
  dependency edges, any violations (a successor that starts before its constraint
  allows), cycles (Kahn's algorithm, with the leftovers reported), and the summary span
  of each parent row.
- **Moving a task pushes its dependants:**
  - `CanvasEditor.reschedule(_:start:due:)` moves or resizes a task.
  - Any dependant that would now break its constraint moves forward by just enough,
    transitively, keeping its duration in working days.
  - Dependants are never pulled earlier.
  - The whole change is one patch.

### Gantt view (NexusCanvas)

- **`CanvasViewMode.gantt`, on ⌘4:** a fourth segment in the toolbar's view switcher.
  Gantt is another view of the same canvas, like Outline (D70): selection is shared, and
  edits go through the same commands and patches.
- **What it shows:**
  - **Rows:** tasks in outline order.
  - **Summary rows:** a topic that isn't a task but has tasks below it is shown as a
    summary row, with a bracket bar spanning its children.
  - **Undated tasks** are listed without a bar.
  - **Collapsed rows:** collapsing a row in the Gantt is view state (D67). It doesn't
    change the topic's `folded` flag.
- **Layout:**
  - **The table on the left** has the columns Task (indented by depth), Owner, Start,
    Due, Days and %.
  - **The timeline on the right** has a header with months and days. Non-working days are
    shaded, a line marks today, and each bar shows its progress fill.
  - **Milestones** are drawn as diamonds.
  - **Dependency arrows** connect the right ends of the bars (as the kind requires).
    Violations and cycles are drawn red.
  - **Scales:** day, week or month. ⌘= and ⌘- step through them while the Gantt is in
    front.
- **One renderer:** `GanttLayout` computes the geometry and `GanttRenderer` draws it into
  a `CGContext`. The on-screen `GanttView` (AppKit) and the PNG, JPEG and PDF exports use
  the same code, so the export matches the screen.
- **Mouse:**
  - Drag a bar to move it, snapping to working days.
  - Drag a bar's ends to resize it.
  - Drag the progress handle to set progress.
  - Drag from a bar's end dot onto another bar to add a finish-to-start dependency.
  - Each drag is one undo step.
- **Accessibility:**
  - The view is an `NSAccessibility` outline with one element per row, for example "Design,
    Ana, 2 Nov to 6 Nov, 5 working days, 40 percent, after Research".
  - Each row has actions to move it earlier or later.
  - The chrome follows D137.
- **Performance:** only visible rows are drawn, and the layout is cached per canvas
  revision.

### Task editor

- **Task… (⌃⌘T), on the canvas, outline and Gantt:**
  - A popover with Start, Due, Duration (working days), Owner, Progress, Priority, Done
    and Depends on.
  - **Depends on** lists each dependency with its kind and lag, and adds a new one from a
    fuzzy topic picker like Quick Jump.
  - Owner offers names already used on the canvas.
  - Dates accept typed shortcuts: `today`, `tomorrow`, `+3` (working days), `fri`, `2/11`,
    `2026-11-02`.
  - Editing Duration moves the due date. Esc cancels. ↩ applies all fields as one undo
    step.
- **The same fields appear as a "Task" section on the Format panel's Data tab.**
- **On the canvas:** a task shows a small task line under its title, drawn like pinned
  metadata, for example "Ana · 2 Nov → 6 Nov · 40%". An overdue open task is tinted with
  the theme's warning colour.
  - The line is drawn in exports and SVG too.
  - VoiceOver's spoken description includes it.
  - Settings › Canvas › Show task details on topics (on by default) turns it off.
- **Filters:** the filter and search fields gain `owner`, `due` (overdue, this week, no
  date) and `task`.

### Keyboard commands

New commands go in the registry. A new `gantt` key scope holds the Gantt's own keys; the
conflict checker treats it like `outline` (D10).

| Command | Key | Scope |
| --- | --- | --- |
| Gantt view | ⌘4 | global |
| Task… | ⌃⌘T | canvas, gantt (palette everywhere) |
| Previous / next task | ↑ / ↓ (⇧ extends) | gantt |
| Collapse / expand row | ← / → | gantt |
| Move a working day earlier / later | ⌥← / ⌥→ | gantt |
| Shorten / lengthen by a working day | ⌥⇧← / ⌥⇧→ | gantt |
| Move a week earlier / later | ⌥⌘← / ⌥⌘→ | gantt |
| Toggle done | Space | gantt |
| Set progress 0, 10 … 90 % | 0…9 (Space marks it done, 100 %) | gantt |
| Link selected tasks, finish to start | ⌘L | gantt |
| Remove dependencies of selected tasks | ⇧⌘L | gantt |
| Schedule from today (undated tasks) | ⌘D | gantt |
| Go to today | T | gantt |
| Timeline scale: day / week / month | ⌘= / ⌘- | global (routed to the Gantt) |
| Edit task name | ↩ | gantt |
| Back to canvas, keeping the selection | Esc | gantt |

Every new command has a palette title and a menu home (View › Gantt, Topic › Task…), so
the keyboard-reachability test covers it.

### Export (NexusCanvas, NexusInterchange)

- **New export sheet group, TASKS:**
  - **Gantt image:** PNG or JPEG, at 1×, 2× or 4×, with all rows or only the selected
    rows' branches.
  - **Gantt PDF:** vector pages with selectable text, fitted to one page or tiled across
    A4 or Letter landscape pages. The table column repeats on each page.
  - **Tasks CSV:** extends today's CSV task list (non-threat maps). New columns: Owner,
    Start, Due, Working days, Progress, Depends on. A "Tasks only" option leaves out
    topics that aren't tasks. Threat models keep their threat table.
  - **Calendar (.ics):** one all-day `VEVENT` per dated task.
    - `DTSTART;VALUE=DATE` and an exclusive `DTEND`.
    - `SUMMARY` is the topic text, prefixed with "✓ " when done.
    - `DESCRIPTION` holds the path, owner, progress and note. `CATEGORIES` holds the
      labels.
    - `UID` is stable per canvas and topic.
    - Lines end in CRLF and are folded at 75 octets, with text escaped.
    - `DTSTAMP` comes from an injected clock (fixed in tests).
- **File › Export Gantt…** opens the sheet on the TASKS group. The Gantt's toolbar has
  the same button.

### Xmind import (NexusInterchange)

- **Zen (`content.json`):** the topic extension `org.xmind.ui.task`, or
  `org.xmind.ui.taskInfo`, is mapped as follows:
  - `status: "done"` → done;
  - `progress` (0–1) → percent;
  - `priority` → priority marker, unless the topic already has one;
  - `start`, `due` (or `startDate`, `dueDate`) as epoch milliseconds or ISO strings →
    calendar dates in the importing Mac's time zone;
  - `duration` with no due → due;
  - `assignee` or `assignees` (string, list of strings, or list of `{name}`) → owner;
  - `dependencies` (`{id, type, lag}`) → `after`, resolved through the existing
    `ref → node` map in `CanvasBuilder`. A lag in milliseconds is converted to days.
- **XMind 8 (`content.xml`):** `<extension provider="org.xmind.ui.taskInfo">` is read
  with the same tolerant key set (`start-date`, `end-date`, `assigned-to`, `progress`,
  `priority`, `prerequisite`).
- **The report:**
  - It counts tasks and dependencies.
  - Fields with no equivalent (such as `creator`) are listed by kind.
  - "Gantt task dates (not in v1)" goes away.
  - Task pies keep becoming progress markers (D91), and the Gantt reads them as progress.
- **Intermediate model:** `ITopic` gains `task: ITask?`, so other importers can use it
  later.

### Decisions to record (D142–D149)

1. Task dates are calendar dates without a time zone, and `due` is inclusive.
2. Priority stays a marker, and progress falls back to the progress marker.
3. Dependencies are stored on the successor (`after`), in working-day lags, within one
   canvas.
4. The work calendar is per canvas. Moving a task pushes dependants forward and never
   pulls them back.
5. Gantt is a view mode (⌘4) with its own key scope. Collapsing rows is view state.
6. One renderer draws the screen and the exports, and the Gantt PDF keeps vector text.
7. ICS uses all-day `VEVENT`s, not `VTODO`s, because Calendar doesn't import to-dos from
   .ics files.
8. Xmind's task extension mapping, including the time-zone rule for epoch dates.

### Changed from the plan

- **Gantt keys:**
  - ↩ opens the Task editor rather than renaming in place. The name is edited on the canvas.
  - Progress keys 0–9 set 0–90%; Space marks a task done (100%).
  - No keys had to change. ⌘D, ⌘L, ⇧⌘L and ⌥⌘←/→ share chords with menu items, so the Gantt claims its own chords before the menu bar while it has focus (D146). ⌘= and ⌘- step the timeline scale while the Gantt shows.
- **Data tab:** the Task section shows the task line, its dependencies and an Edit Task… button, rather than repeating every field.
- **Overdue tasks** are marked with ⚠︎ in their task line rather than tinted, so no new drawing path was needed.
- **Export Gantt…** is in the File menu and the palette, and opens the sheet on the TASKS group. There's no extra toolbar button.
- **Schema:** the fields carry descriptions but no `x-since` notes, because the schema has no such convention.
- **Cycles:** `validate()` reports dependencies on missing topics, not cycles. Repair can't fix a cycle without guessing which link to drop, and a loaded document must validate (D126). The Gantt draws cycles red instead.

### Defects found during M11 and fixed

- **Control-0 dropped task fields:** it rebuilt the to-do as `Todo(done:)`.
- **The fuzzer crashed the loader** with a huge number in `schedule.workdays`; it's now bounds-checked before converting to `Int`.
- **The Gantt was slow:** `snapForward` and `snapBack` used `for … where`, which always ran 4,000 iterations. A 1,000-task layout took 196 ms; it now takes 18.
- **Found by `axaudit`:**
  - The canvas's topic elements stayed in the tree behind the Gantt. The canvas view is now hidden while the Gantt shows.
  - The Gantt rows read as unknown elements, because they were released before the client read them. They're now cached per topic.
  - A dependency picker read "Kind, Kind"; it's now "How it waits for Code".
