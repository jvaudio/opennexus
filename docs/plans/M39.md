# M39 · One catalogue: diagram descriptors and starters

The foundation for the starter picker (M40), Guide mode (M41) and Present, part 4 (M42).
See `starters-guide-present.md`.

## Plan

**Goal:** one place says what each diagram type is, and templates become data. Users see
no change, apart from one colour: see D287.

**Accept when:**

- **A1 · One table.** `DiagramDescriptor.all` holds every per-type trait:
  - name, default structure, root text and new-topic text;
  - tint;
  - technical, asks for node types, root is title;
  - node-type palette and inference;
  - picker category, summary and search aliases.

  Every per-type `switch`, and every list of *all* types, reads from it:
  - `Canvas.swift`: `defaultStructure`, `displayName`;
  - `DiagramCatalog`: `nodeTypes`, `isTechnical`, `asksForNodeTypes`, `rootIsTitle`, `effectiveType`;
  - `defaultTopicText`;
  - `defaultRootText`;
  - `HomeView.typeName` / `tint`;
  - the tab colour;
  - `diagramType(for:)`;
  - `MapTools.types`;
  - the localisation test's list.

  Orderings a single screen designed stay with that screen: Home's seven cards, and
  Convert's 1–8 tiles (artboard 10). Type checks for a feature of one type (`type == .dfd`
  for the DFD panel), rendering, and file-format mappings (Xmind, Mermaid) are not trait
  tables and stay.
- **A2 · Starters are data.** The 25 templates become JSON files in
  `Sources/NexusCanvas/Starters/`, validated by `schema/starter.schema.json`. Each holds:
  - id, name, summary, kicker;
  - shelf (Home's role shelf) and category (the picker's);
  - aliases;
  - type, canvas title, outline lines and relationships.

  `StarterLibrary` loads them, and adds a generated **Blank** starter per diagram type.
  `MapTemplate` and `TemplateLibrary` are replaced.
- **A3 · Nothing moved.** Every JSON starter builds a canvas whose canonical JSON is
  **byte-identical** to what its Swift template built. This is checked against fixtures
  captured from the Swift templates before they're deleted.
- **A4 · Localised.** Starter names, summaries and kickers, and type summaries, are in
  `Localizable.xcstrings`. `catalogCoversEveryDataDrivenString` enumerates them from data.
- **A5 · Agents.**
  - `nexus new --starter <id>` creates a document from any starter.
  - `nexus starters` lists them (id, type, name).
  - `--type` still works, and both read the descriptors.
- **A6 · Schema debt.** `nexus.schema.json` (and its `NexusFormat` copy) declares the
  canvas's `presentation` and `filters`, and the node's `presentHidden`. Swift already
  writes them; the schema didn't say so. A document using all three validates.
- **A7 · Quality.**
  - `swift test` and `scripts/lint.sh` pass, and the app builds.
  - Home's snapshot is unchanged, apart from template kickers that were not localised before.

### Design

**`DiagramDescriptor`** (NexusCore, `Descriptors.swift`), a value type:

```swift
public struct DiagramDescriptor: Sendable {
    public var type: DiagramType
    public var name: String            // English; the UI wraps it in Loc.t
    public var summary: String
    public var category: StarterCategory
    public var aliases: [String]       // search terms, not localised
    public var structure: LayoutStructure
    public var rootText: String
    public var topicText: (main: String, sub: String)
    public var tint: String            // hex, from the design's Home recents
    public var technical: Bool
    public var asksForNodeTypes: Bool
    public var rootIsTitle: Bool
    public var palette: Palette        // .none, .flow, .dfd, .threat, .icons, .sequence
    public var inference: Inference    // .none, .flow, .dfd, .architecture, .sequence
}
```

- `DiagramDescriptor.all` lists the 16 types in `DiagramType`'s declaration order.
- `DiagramDescriptor[type]` falls back, for an unknown type from a newer file, to a mind-map-like descriptor named after its raw value. This matches today's `default:` branches.
- The existing API (`DiagramType.displayName`, `.defaultStructure`, `DiagramCatalog.isTechnical(_:)` …) stays, as one-line forwarders, so call sites don't churn.
- `effectiveType` switches over `inference`, not over the type.
- `defaultTopicText` keeps its timeline quirk (Event at depth 1 only) through `topicText`'s main and sub values.

**Starter JSON** (one file per starter):

```json
{
  "id": "oauth",
  "name": "OAuth handshake",
  "summary": "Lifelines with return messages",
  "kicker": "SEQUENCE",
  "shelf": "engineering",
  "category": "software",
  "aliases": ["oauth", "login", "auth"],
  "type": "sequence",
  "title": "OAuth handshake",
  "outline": ["OAuth handshake", "  User >actor", "  App >participant", "  Auth server >participant"],
  "relationships": [
    { "from": "User", "to": "App", "label": "Sign in" },
    { "from": "Auth server", "to": "App", "label": "Code", "kind": "return" }
  ]
}
```

- `outline` uses today's template syntax: two spaces per level, and `Text >nodeType`.
- `relationships` connect topics by their text, matching the first topic in outline order. That's
  deterministic, unlike today's dictionary lookup; all 25 templates use unique texts.
- The build runs the same `CanvasEditor` operations, in the same order, as `TemplateLibrary.outline`.
- Every template's explicit `layout.structure` equals its type's default, which `Canvas.init`
  already sets, so starters don't carry `structure`.

**Categories:** `thinking`, `planning`, `process`, `architecture`, `security`, `software`.
Home's shelves (`engineering`, `architecture`, `security`, `planning`, `learning`) stay as
`shelf` until M40 replaces the shelf.

**Loading:**
- `Package.swift` copies `Starters/` into NexusCanvas's bundle (`.copy`), keeping one file per
  starter, ordered by an `order` integer, so Home's order holds.
- A starter that fails to decode is a test failure, never a silent skip, because only built-ins
  load in M39.

### Visible changes

- **Tab squares** take the type's colour from Home (D287): a mind map's tab is teal (was iris), a DFD's violet (was teal).
- **Home › More…** says "Tree Chart" and "Brace Map" (was "Tree" and "Brace").

### Known gaps

- Neither visible change was checked by hand in the running app.
- MCP doesn't list starters yet; the CLI does.
- Categories, aliases and summaries are data only until M40's picker shows them.
- The `guide` schema entry moves to M41, when guides exist.
- The starter files add about 75 KB to the app: the canvas bundle is also copied into the two Quick Look extensions.
