# M50 · Larger starter gallery

Phase 8 of `collaboration-and-reach.md`: the built-in starters grow from 25 to 100, every
diagram type gets at least three, and people can save, export, install and manage their
own. The M40 picker stays fast and keyboard-friendly at that size.

Decision #16 was confirmed on Oct 31, 2026: about 100 built-in starters, 75 of them new
(D465).

## What we know before starting

- **Starters are data** (M39, D288): one JSON file each in `Sources/NexusCanvas/Starters/`,
  checked against `schema/starter.schema.json`. A starter is an outline (`"Text >nodeType"`,
  two spaces a level) plus relationships found by topic text. It builds its canvas through
  the editor's own operations. `StarterFixtures/` pins the canvas each of the 25 builds
  (M39 A3).
- **The 25** have 4–11 topics and no notes, edge labels, boundaries or lanes. By type: mind
  map 5; matrix and timeline 3 each; architecture, flowchart, logic and tree table 2 each;
  data flow, fishbone, org, sequence, threat model and tree 1 each; brace, swimlane and
  whiteboard none.
- **Two groupings exist already:** `category` (the picker's six, also used by For You) and
  `shelf` (Home's five role shelves, five starters each, drawn as one row of cards). The
  phase's ten shelves are neither.
- **The picker** (`StarterGallery`, `StarterGalleryView`) has All, Recent, For You and the
  six categories in its sidebar, searches names, aliases, kinds, categories and summaries,
  and draws thumbnails lazily, one card per run-loop turn, cached per session.
- **Guides** (M41) exist for the mind map, flowchart, data flow, threat model and
  architecture; `GuideMatcher` says which steps a canvas meets. A data flow's arrows are
  tree edges (labelled by the child's `edgeLabel`) and relationships; `DFDRules` checks
  them. Threat models need a trust boundary; swimlanes need lanes
  (`DiagramData.lanes`, a topic's `lane`).
- **Names, summaries and kickers** go through `Loc.t` and must be in the string catalog
  (`LocalizationTests`).
- **The App Group** (`<TeamID>.com.opennexus`) is shared by the app, its extensions and
  `nexus`, which finds it without asking the system (`AppGroup.container(team:)`).
- **The network service** can already read a URL as it is, from the URL's own host with no
  credentials (M47d's `read` job, behind the network switch).

## Plan

### Schema and loader

- New optional fields, so every existing starter stays valid:
  - `collection`: the picker's shelf (`business`, `engineering`, `product`, `process`,
    `planning`, `thinking`, `security`, `architecture`, `personal`, `meetings`). It's a
    third field, not new categories: categories still drive For You, and `shelf` still
    drives Home (D466).
  - `note`: the root topic's note, saying how to use the starter.
  - `details`: per topic, found by text like relationships: `note`, `edge` (the label on
    the edge into it), `markers`, `todo` (done or progress) and, for scheduling starters,
    `start` and `days` counted from the day the starter is used.
  - `boundaries` (title, topics, meaning and trust) and `lanes` (title, topics).
  - `structure`: the canvas's layout, when it isn't the type's default (an alternating
    timeline).
  - `document`: a whole one-canvas `.nexusjson` document, for starters saved from a canvas.
    It replaces `outline`; the schema requires one of the two.
- The 25 get a `collection` and nothing else, so the canvases they build don't change.
  Their Home shelves stay as they are; the new starters have no `shelf` (D466, D467).

### Your own starters

- **Save Canvas as Starter…** (File, the tab menu, ⌘K) asks for a name, collection,
  summary and aliases, and saves the canvas, with its assets, as a starter file in the App
  Group's `Starters/` (the app's container when there's no group). They show in a My
  Starters shelf. Creating from one gives the canvas with fresh ids.
- **Export Starter…** writes a `.nexusstarter` file; several selected in My Starters export
  as a `.nexusstarters` pack. Both are new document types: opening one shows a preview
  and asks before installing.
- **Install Starter…** from a file, by dropping one on the picker, or from a URL when the
  network service is on (read like an Open in OpenNexus link, then previewed). Starters
  are data; an install never overwrites without asking (Replace or Keep Both), and a
  malformed file is refused with a message saying what's wrong.
- **Manage** in My Starters: rename, edit details, move to another collection, delete
  with undo, Show in Finder.
- `nexus starters` and the MCP `list_starters` include the user's starters when the App
  Group can be read; `nexus starter install <file>` installs one or a pack.

### The picker at 100+

- The sidebar: All, Recent, Favourites, For You, My Starters, then the collections with
  counts (the categories leave the sidebar but stay in search). A card's ☆ and ⌘D mark a
  favourite; favourites and recents persist in preferences.
- Search also covers the collection and the type's name.
- Thumbnails stay lazy; the picker opens in under 100 ms with 150 starters.

### Tests

- **Content lint** (`StarterContentTests`): 12–40 topics, topic text of six words or fewer,
  two or more aliases, a root note, no banned words (placeholder text, real companies,
  products and people), details and relationships naming real topics, node types the
  type knows. The 25 are held to the rules they already meet (aliases, text length,
  banned words). It's a Swift test so `swift test` runs it.
- **Layout:** no two topics overlap in any starter's laid-out canvas.
- **Guides:** each new starter of a guided type meets its guide's required steps, and the
  data flows and threat models break no DFD rule.
- **Goldens:** a PNG of each of the 100 at 1×, light, compared like the style goldens
  (`ImageDiff`), reviewed by eye on contact sheets before they're committed.
- **Your own starters:** save then create gives an equal canvas apart from ids; export and
  install round-trip for one starter and a pack; malformed files, unknown versions and
  oversized files are refused; Keep Both and Replace; delete and undo.
- **Picker:** collections and counts, Favourites and Recents persisting, search by alias and
  collection, the arrow keys, and opening in under 100 ms with 150 starters.
- **CLI and MCP:** listings with user starters, `starter install`.

### Built

- **75 starters** in `Sources/NexusCanvas/Starters/`, written to a brief (`StarterContentTests` holds its rules) in four batches and reviewed on contact sheets. Every one has a root note on how to use it; most have notes on their main blocks, labelled flows, markers that teach (priorities, ratings, votes) or dated tasks.
- **Schema and loader:** `collection`, `note`, `details`, `boundaries`, `lanes`, `structure` and `document` (D468); `Starter.json` writes a starter back out.
- **My Starters** (`MyStarters`, `StarterFile`): the folder, `.nexusstarter` and `.nexusstarters`, save, update, remove and restore, install with Replace or Keep Both (D474, D476).
- **The picker:** collections in the sidebar with counts, Favourites (☆, ⌘D), My Starters with Install Starter…, Install from URL… and Export All…, a card menu for your own (Rename…, Edit Details…, Move to, Export Starter…, Show in Finder, Delete), Undo in the footer, drops (`StarterSheets.swift`: the details form, the install preview, the URL form).
- **The Mac app** (`App/OpenNexus/Starters.swift`): Save Canvas as Starter… as a sheet, Install Starter… from any window, and `.nexusstarter` / `.nexusstarters` as document types opened into the installer (`AppDocumentController`). iOS declares the two types so the picker's Install Starter… can choose them.
- **Network:** `ShareCenter.readStarter` (D477).
- **CLI and MCP:** `nexus starters`, `nexus starter install`, `new --starter` and `list_starters` with the user's own (D480).

### Changed from the plan

- **Export All… instead of exporting a multi-selection** (D478): the grid keeps its one selection.
- **Delete is immediate with Undo in the picker's footer**, not the document's undo stack (the picker has none).
- **Collections stay a third field and Home's shelves keep their 25** (D466), as the plan set out; the categories leave the picker's sidebar but stay in search.
- **The 25 are held to the rules they already met** (D467): the ADR starter still names its queue products.

### Defects found

- **Fit to Window, export, the minimap and thumbnails cut a sequence diagram off below its participants** (D473). `Scene.bounds` now includes the lifelines. No existing golden or fixture held a sequence diagram's export, and the web fixtures `npm run check` regenerates came out unchanged.
- **A saved starter with an empty summary would have been written and then refused when read back**, so it would have vanished. `MyStarters.write` now reads every file back before writing it, and an empty summary becomes the type's name.
- **Creating from a saved starter assumed `DocumentModel.add` would use the id it was handed**; it now takes the id `add` returns.

### Known gaps

- **Some starters lay out very wide** (the three swimlanes, the story map, workshop agenda, study schedule, value stream and kill chain), so their picker thumbnails are thin strips and their goldens small; they read well zoomed in.
- **Relationship curves that bow outside the topics are outside `Scene.bounds`**, so an export can clip the curve (seen while writing the data-pipeline starter). Not changed here.
- **Scheduled tasks count calendar days**, so a task can start on a weekend in the Gantt view (D470).
- **Opening a `.nexusstarter` from Finder and Install from URL… weren't tried in a running app**; both are covered by the model tests and the app builds. URL installs need the network switch on.
- **The unhandled-files warning** for the test target now counts the 100 new PNGs too (the existing goldens weren't declared either).
