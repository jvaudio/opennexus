# M46 · Real-time co-editing

Phase 4 of `collaboration-and-reach.md`: several people edit one document at the same
time from their own Macs. They see each other's selections and edits as they happen,
every copy ends up identical, ⌘Z undoes only your own changes, and the relay sees only
sealed bytes.

Decisions #10 (invite links are universal links) and #11 (a native CRDT, with Loro as
the fallback) were confirmed on Oct 29, 2026 (D366–D367). Universal links need the custom
domain (still to be named) and a team-signed app; until then the viewer site's join page
opens the app with `opennexus://join#…` (D366).

## Plan

### Replication (`NexusReplica`, a new platform-neutral module on `NexusCore`)

The `.nexus` file stays canonical JSON. The replica is metadata kept beside it while a
session lasts; the document is always what the replica materialises.

- **Clock**: a replica id per join (6 random base-36 characters) and hybrid logical clock
  stamps (milliseconds, counter, replica). Stamps order every op totally.
- **State**, all of it a function of the set of ops received, so delivery order and
  duplicates don't matter:
  - *Registers* (last writer wins by stamp): each topic field (every key of the topic's
    JSON but `children` and `comments`); each element's fields (relationships,
    boundaries, summaries, callouts, zones, by element id); canvas settings by key path
    (`title`, `type`, `root`, `legend`, `filters`, unknown keys; `layout.*`, `style.*`,
    `diagram.*`, `presentation.*`, `guide.*`, `schedule.*`); the document theme by
    top-level key.
  - *Tree* per canvas (Kleppmann's move operation): each topic's parent and position. A
    move is applied in stamp order; one that arrives late undoes the later moves, applies,
    and redoes them; a move that would make a cycle does nothing. Parents are topics or
    four virtual roots: the canvas root, floating topics, element topics (summary and
    callout topics) and the trash. Delete is a move to the trash.
  - *Places* (an ordered set, last writer wins per item): canvases and their tab order,
    each canvas's elements in order, each topic's comments (identified by content).
  - *Assets*: added, never removed (they're content-addressed).
- **Positions**: fractional index keys (base-62 strings) with a fixed-length unique
  suffix from the replica and a counter, so two keys are never equal and a key always
  exists between two others; siblings sort by key.
- **Materialise**: a canvas is its registers, its tree (reachable from the root, the
  floating topics and the element topics; the trash and anything under it is gone) and
  its places. A canvas whose references dangle after concurrent edits (a relationship to
  a deleted topic) gets the existing deterministic `repair()`, so it's the same everywhere.
- **Local edits**: every committed `Patch` is diffed into ops (field sets, moves with new
  position keys for only the topics whose place changed, places, assets). Moves are
  emitted in the new tree's breadth-first order, so no intermediate state makes a cycle.
  After applying them, the replica's materialisation equals the edited document (checked
  in tests and, cheaply, in debug builds).
- **Remote ops** become ordinary `Patch`es (per canvas, plus one for canvases, order and
  theme), so drawing, VoiceOver, autosave and the outline need no new paths. Only the
  topics and canvases the ops touched are rebuilt.
- **Ids**: during a session new topic, element and canvas ids carry the replica as a
  suffix (`n12-k3x9qa`); the schema's id pattern admits it. `Canvas.idSuffix` and
  `DocumentModel.idSuffix` are in memory only. Every reader of ids is checked (natural
  sorting, sequence seeding).
- **Undo**: remote patches never enter your undo stack. Each local commit's ops are kept
  with the values they replaced; undo emits inverse ops only for registers, moves and
  places that still hold what you set (same stamp), so it never reverts someone else's
  later change. Redo is the same over the undo's ops. The session clears pre-session undo
  history when it starts.
- **Snapshot**: the state as a compact op list (winning register writes, all moves,
  places, assets). Applying a snapshot is a state merge, so a late joiner is an empty
  replica plus the snapshot plus the op tail.
- **Persistence**: the replica, unsent ops and the last relay sequence are kept in the
  app container by session, so a crash or an offline stretch resumes and converges.

### Session client (`NexusReplica`)

- **Invite link** `<viewer>/join#2.<server>.<room>.<key>.<read>[.<write>]`, all base64url;
  `opennexus://join#…` carries the same fragment. The room key seals everything; the read
  and write capabilities are random secrets whose SHA-256 the relay keeps. A view-only
  invite has no write capability. The host also keeps an end secret.
- **Messages** (sealed with the room key, `Sealed` envelopes, D331): op batches
  `{replica, seq, ops}`, presence `{replica, name, colour, canvas, selection, editing,
  viewport, pointer}`, snapshots and the join page's viewer bundle.
- **`RoomClient`**: hello, welcome (snapshot and tail), acks, an outbox resent after a
  reconnect, back-off from 0.5 s to 30 s, presence throttled to 10 a second, and a
  snapshot when the relay asks. Transport-neutral, so tests run it in memory and against
  the real relay.

### Network service

- **WebSocket** in `NexusNet` (`URLSessionWebSocketTask`), allow-listed like HTTP; the log
  gets one entry when a socket opens and one with its byte totals when it closes.
- **XPC**: a socket is its own connection to `OpenNexusNet.xpc` with an interface each
  way (`openSocket`, `send`, `close`; `received`, `closed`). Rooms are created and ended
  with two new jobs (`createRoom`, `endRoom`).

### Relay: OpenNexus Server, part 2

- `POST /v1/rooms` (upload token; the capabilities' SHA-256) → `{id}`.
  `DELETE /v1/rooms/{id}` (end secret) closes the room and deletes its data.
  `GET /v1/rooms/{id}/view` (read capability) → the latest sealed viewer bundle.
- WebSocket `/v1/rooms/{id}`: `hello` (a capability) → `welcome` (role, members,
  snapshot, op tail since the client's last sequence); `ops` (write only; numbered,
  stored, fanned out, acknowledged); `presence` (fanned out, never stored); `snapshot`
  (write only; replaces the stored one and drops the tail it covers); `joined`, `left`,
  `ended`, `error`. When the tail passes 200 ops the relay asks one writer for a snapshot.
- Rooms are kept in memory and written through to `OPENNEXUS_ROOMS_DIR` (sealed bytes
  only). Deleted on End Session or after `OPENNEXUS_ROOM_IDLE_DAYS` (7) without a
  connection. Limits: message size, room size, members per room, rooms per server,
  messages per second per connection.

### App

- **Settings**: Privacy & Data › Network gains "Live co-editing (Labs)" (`network.collab`,
  off). Your name is Settings › Editing › Comment author (or the Mac's user name); your
  colour comes from the replica id.
- **File › Collaborate…** (also in the share menu): pick an OpenNexus Server from
  Settings › Sharing and "Can edit" or "Can view", then Start. The sheet shows the invite
  link (QR, Copy, share menu), who's here, and End Session (host) or Leave Session.
- **Joining**: an invite link (universal link, `opennexus://join`, or File › Join
  Session… with a pasted link) opens the session's copy, saved in the app container until
  you choose a place (File › Move To…). Without the network switches on, the app says so
  and opens the right Settings pane.
- **During a session**: the toolbar's avatar row and status pill ("Live · 3 people",
  "Reconnecting…", "Offline · changes wait"); each person's selection ring and name tag in
  their colour, with an "editing" mark on topics being typed in; clicking an avatar
  follows that person's view until you scroll or click; typing in a topic someone else is
  editing shows a gentle hint. VoiceOver announces joins, leaves, and who is editing the
  focused topic.
- **Resume**: reopening a document that's in a session reconnects it; what changed offline
  goes out then.

### Web

- `site/join/`: the join page reads the fragment, offers "Open in OpenNexus"
  (`opennexus://join#…`) and the download, and draws the last shared snapshot with
  viewer-core (read-only).
- `site/.well-known/apple-app-site-association` for `/join/*`.

  undo and the undo property test inside a session (A3); snapshots and late joiners (A6);

- Server: room auth, capabilities, fan-out, retention, limits, and a load run (A9).
- `NexusCanvasTests`: a session bound to a `DocumentStore` and controller: remote patches

- Web: the join page in Vitest and Playwright.

### Built

- **NexusReplica** (new, platform-neutral, on NexusCore and NexusFormat): hybrid logical
  clocks and replica ids; fractional position keys; ops for registers, tree moves (with
  late moves undone and redone, and cycles ignored), places and assets; the replica
  (seeding from a document, recording a `Patch` as ops, receiving ops as patches,
  materialising, snapshots, selective undo and redo, saving); invites; the sealed room
  messages and presence; and `RoomClient` (hello, welcome, acks, the outbox, back-off,
  presence throttling, snapshots on request), transport-neutral.
- **Network service.** `NetSocket` (WebSocket, allow-listed, logged with byte totals);
  each socket is its own XPC connection with events back to the app; `createRoom` and
  `endRoom` jobs.
- **OpenNexus Server, part 2.** Rooms: create, end, the join page's view, and the
  WebSocket relay with persistence, retention and limits; the settings in its README.
- **App.** `CollabCenter` and `CollabSession` (start, join, resume, suspend, leave, end;
  the Keychain and container records); `DocumentStore` hands commits to the session and
  applies remote patches outside undo; the Collaborate and Join Session sheets, the network
  notice, the toolbar's avatars and status pill, presence rings and tags, following, the
  hint and announcements; File › Collaborate… and Join Session…; Collaborate… in the Share
  menu; invite links from `opennexus://join` and web links; "Live co-editing (Labs)" in
  Settings › Privacy & Data.
- **Web.** The join page (`site/join/`): the invite bar with Open in OpenNexus and the
  download, and the host's last view, decrypted in the page; the
  `apple-app-site-association` file.
- **Tests and scripts.** `NexusReplicaTests` (PositionTests, ReplicaTests,
  ConvergenceTests, SelectiveUndoTests, InviteTests, RoomMessageTests, RoomClientTests),
  `CollabTests` (11), the live `CollabLive` (2) with `scripts/test-collab.sh`,
  `JoinFixtures` for the web tests, the server's `RoomTests` (13), the join page in
  Vitest (7) and Playwright (8 across Chromium and WebKit).

### Changed from the plan

- **A4 was measured on this Mac, not two Macs on a network:** the server in Docker on
  loopback, four windows in one process. The relay's hop (2.7 ms) is the network's share;
  most of the 34 ms is four debug-build windows sharing one main thread.
- **The invite link is `<viewer>/join/#…`**, with a slash, because the viewer site is a
  static site whose join page is `join/index.html`.
- **The join page shows the host's last view**, a sealed viewer bundle the host refreshes
  at most every 30 s (D371), rather than a snapshot of the replica: the browser needs
  layouts, which only the app makes.
- **View-only edits are turned away in the app too** (D377), not only by the relay.
- **Ending or leaving clears undo as well as starting** (D376).
- **Reopening takes the replica's state** (D372); the plan said only that the session
  resumes.
- **The pointer isn't shared yet:** presence has room for it, but only selection, editing
  and the visible area are sent.
- **Join Session… needs a document window** (D374); links don't.

### Defects found

- **The server didn't build on Linux.** Reading counts out of frames used CoreFoundation
  to tell `true` from `1`, which isn't there on Linux; the macOS tests passed and the
  Docker build for the live run failed. Frames are decoded with `Codable` now, and
  `framesReadCountsStrictly` checks `true`, negatives, fractions, strings and huge numbers.
- **The Collaborate sheet redrew its QR code, with a new Core Image context, each time
  someone moved** (about 20 ms of the main thread each time, in debug). Found by sampling
  the live latency test: the median went from 45 ms to 32 ms with the code made once.
- **⌘Z could undo the wrong step in a session.** An undoable change that changed nothing
  shared (a selection) registered an undo step but no replica step, so the two stacks fell
  out of step. Every undoable change is a replica step now, even an empty one.
- **The join page had two main landmarks and two banners** once the viewer was drawn
  (axe, in Playwright); the invite bar is a named region and the view replaces the page's
  main.

### Known gaps

- **Universal links wait for the custom domain and a team-signed app** (D366). The
  association file's app id has a placeholder team, and the join page opens the app with
  `opennexus://join#…`.
- **Join Session… needs a document window**; with none open, use an invite link.
- **Edits made to a session's document by other means while it was closed are lost**
  when it reopens (D372), and Revert or a restore that replaces the whole document during a
  session isn't sent to the others.
- **The browser view is up to 30 s behind, and only the host refreshes it**; with the
  host away, it stays as they left it.
- **Concurrent typing in one topic keeps the last commit** (character-level merging is out
  of scope); the hint says when someone else is typing there.
