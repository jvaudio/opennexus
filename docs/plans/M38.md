# M38 · Software updates

## Plan

**Goal:** when a new release is published, installed copies can find out and update:
- a notice and Check for Updates…;
- the choice to check automatically, and to download and install automatically;
- a Beta channel.

The promise "no network" (README §12) bends as little as possible: updates are opt-in,
signed, and fetched by a separate service, not by OpenNexus.

**Accept when:**
- **A1 · Opt-in:** nothing is fetched until the user turns checks on (Settings › General ›
  Updates, or Sparkle's own question on a later launch) or chooses Check for Updates….
  Both switches are off by default.
- **A2 · The app stays offline:** OpenNexus keeps no network entitlement, and
  `NetworkPrivacyTests` still bans networking APIs in its code. Sparkle's Downloader
  service fetches the feed and the update; its Installer service replaces the app.
- **A3 · Signed:** an update must be signed by the project's EdDSA key and the same
  Developer ID. A wrongly signed one is refused.
- **A4 · In the app:**
  - OpenNexus › Check for Updates….
  - Settings › General › Updates: check automatically, install automatically, channel
    (Stable or Beta), Check Now, and where updates come from.
  - Privacy & Data says what can leave the Mac.
  - The Settings rows and Sparkle's own settings stay in step.
- **A5 · Releasing:**
  - `release.sh` signs Sparkle's parts and the DMG, and adds the release to
    `appcast.xml`.
  - `publish.sh` creates the GitHub Release, then pushes the feed.
  - The whole path is tested end to end on this Mac.

## Results (2026-10-24)

| | Result |
| --- | --- |
| A1 | **Met.** Info.plist sets no `SUEnableAutomaticChecks`, so Sparkle asks before its first check. `general.updatesCheck` and `general.updatesInstall` default to off (tests: `SettingsTests.networkRowsAreLockedOff`, `NetworkPrivacyTests.updatesAreOptInAndSigned`). | A3 | **Met.** `SUPublicEDKey` holds the key from `generate_keys --account opennexus`, whose private half is in the login keychain. `SUVerifyUpdateBeforeExtraction` is on. End to end: an update with a wrong EdDSA signature was downloaded but never staged or installed. |
| A4 | **Met.** `App/OpenNexus/Updates.swift` owns `SPUStandardUpdaterController`. ### Built

- **Sparkle 2.10.0**, through Swift Package Manager: `make_project.py` gains remote packages (`XCRemoteSwiftPackageReference`), and `Package.resolved` pins the version. It's in the app target only; `Package.swift` and the extensions are unchanged.
- **Info.plist:** `SUFeedURL` (`https://raw.githubusercontent.com/jvaudio/opennexus/main/appcast.xml`), `SUPublicEDKey`, the two service switches, `SUVerifyUpdateBeforeExtraction`, and `SUScheduledCheckInterval` (one day).
- **`release.sh`:**
  - Signs Sparkle's Downloader (with Sparkle's `Downloader.entitlements`), Installer, `Autoupdate`, `Updater.app` and the framework with the Developer ID, then re-signs the app around them. Xcode re-signs only the framework, and its parts ship signed ad hoc.
  - Checks all twelve signed parts.
  - Signs the DMG with `sign_update`, and runs `appcast.py`.
  - `BUILD=`, `NOTARIZE=0`, `FEED=` and `URL_PREFIX=` are for test builds.
- **`appcast.py`:** keeps the feed: every release, newest first, one item per build, optionally on the `beta` channel, with a link to the release notes that opens in the browser.
- **`publish.sh`:** tags the build, creates the GitHub Release with the DMG and its SHA-256, and only then commits and pushes the feed.
- **`appcast.xml`:** starts empty, so the feed exists before the first update.
- **Version:** 0.2.

### Known gaps

- **0.1 can't update itself;** 0.2 is installed by hand once.
- **The feed itself isn't signed.** Sparkle 2.10 can require a signed feed (`SURequireSignedFeed`), and `sign_update` can sign `appcast.xml`. The updates are signed, which is what Sparkle requires; signing the feed too is a hardening step for later.
- **Debug builds can't update.** Sparkle's parts are signed only by `release.sh`.
- **Release notes are a link,** opened in the browser, not shown in Sparkle's window. The app loads nothing itself.
- **Installing a downloaded update in place is only tested end to end with automatic installs.** Sparkle's own window ("Install and Relaunch") wasn't clicked through.
- **The update signing key lives only in this Mac's keychain** until it's exported and backed up (README › Make a release).
