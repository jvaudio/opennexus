# Decisions

Choices made where the design was silent or ambiguous, each with a one-line rationale
(per the agent prompt). Newest at the bottom of each milestone.

## M0 · Foundations

| # | Decision | Rationale |
| --- | --- | --- |
| D1 | **Undo is patch-based**: every edit runs through `CanvasEditor`, which records the before-image of each touched node (and of the non-node canvas fields when they change). A `Patch` is invertible and mergeable. | One mechanism covers typing, restructuring, style, layout mode, conversion and AI accepts; coalescing and "Merge = one undo" fall out of `Patch.merged`. Cheap at 5k nodes because only touched nodes are copied. |
| D2 | **Canonical JSON writer of our own** (sorted keys by code point, 2-space indent, `"key": value`, LF, trailing newline, integers without `.0`). `JSONEncoder` is not used for files. | Foundation's pretty printer writes `"key" : value` and its number formatting is not guaranteed stable; byte-identical round trips need full control. |
| D3 | **Defaults are omitted** on write (`folded: false`, empty `markers`, `ai: false`…), but `text`, `kind` and `children` are always written. | Smaller files and quieter diffs. Round trip is byte-identical for files in canonical form; a hand-edited file is normalised once on first save. |
| D4 | **Unknown keys round-trip** via an `extra` bag on every model type, at every level (manifest, canvas, node, todo, note, relationship, layout, style). Elements that later milestones type (zones, boundaries, summaries, callouts, `diagram`) already round-trip through the canvas's `extra`. | Forward compatibility requirement in README §6. |
| D5 | **Node ids are sequential per canvas** (`n1`, `n2`…), seeded from the highest existing id on load. Node keys in `nodes` are sorted lexicographically like every other object key. | Diff-friendly and deterministic; one sort rule for the whole file. |
| D6 | **Open string enums** (`DiagramType`, `NodeRole`, `LayoutStructure`, `LayoutMode`) instead of Swift enums. | Values from newer files are preserved instead of failing to decode. |
| D7 | Schema allows unknown keys everywhere except inside `nodes` (whose keys must be ids). `nexus validate` also checks tree invariants (one parent per node, reachability, dangling relationships). | JSON Schema cannot express tree invariants; forward compatibility needs open objects. |
| D8 | **Node typography follows P0** (root 20 / main 15 / sub 13.5 pt) rather than artboard 02's 22 / 16 / 14. | P0 is "the reference for feel" and artboard 07 also labels Central as 20 pt; all sizes stay ≥ 12 pt. Theme data can override later. |
| D9 | **Layout spacing follows P0** (main sibling gap 20, deeper 10, root→main 64, parent→child 40) rather than the token sheet's 14 / 56 / 28. | Same reason as D8; screenshots 06 and 17 were captured from P0's values. |
| D10 | **Commands have scopes** `global`, `canvas` (Select), `editor` (Edit), `connect`, `outline`, `find`. Global conflicts with every scope; others only with themselves. | Lets ⌘K be the palette in Select mode and Link in Edit mode, as the brief specifies, while keeping the conflict test strict. |
| D11 | **Xmind alias set lives in the default profile**: ⌘R → Relationship (Connect mode), ⌘⌫ → Delete keeping children, ⌘; → Focus. | Review row asks for the aliases; ⌘R's Xmind meaning is unconfirmed, so it maps to the closest OpenNexus command. Revisit if a user reports a mismatch. |
| D12 | **Profiles**: OpenNexus (default), Hyper-first, Outliner (Tab demotes, ⌥↩ adds a child), Vim-style (`h j k l`, `i`/`a` edit, `o`/`O` siblings, `x` delete, `z` fold, `g` root; typing does **not** replace the selection). | Brief names these profiles; Vim beyond the basics is under-specified (README §14). Chords cannot express `dd`, so `x` deletes. |
| D13 | **The app is AppKit-lifecycle** (`NSApplication` + `NSDocument`, programmatic menus) with SwiftUI hosted for panels and settings. | Menus must be generated from the registry and the canvas needs first-responder control; the document needs file-package autosave and versions. |
| D14 | **Sandboxed with no network entitlement.** | "Local and owned": the OS enforces that the app cannot open connections. |
| D15 | The Xcode project is hand-maintained and uses **synchronized folders** (`App/OpenNexus/` is picked up automatically). All logic lives in the Swift package; the app target is thin. | Keeps the project file tiny and merge-friendly; no generator dependency for contributors. |
| D16 | **MIT licence** (product owner's choice, 2026-10-14). | README §4 left Apache-2.0 vs MIT to the product owner. |

## M1 · Canvas and keyboard core

| # | Decision | Rationale |
| --- | --- | --- |
| D17 | **Branch lines are recomputed every frame from animated node frames** (display-link spring stepping) instead of separate Core Animation path animations. | Lines stay glued to nodes through overshoot, and new input retargets springs in flight (motion rule 2). |
| D18 | **Node text is measured and drawn with AppKit string drawing (TextKit)**, the same engine as the `NSTextView` editor. | One engine for measure, draw and edit removes P0's mid-word wrap artefact (README §14). |
| D19 | **The editor opens at the node's final frame**; the node's shape grows in behind it. | Caret live at 0 ms while the creation animation still plays (brief §8). |
| D20 | **Creating a topic and naming it are two undo steps** (as in Xmind and P0). | Native `NSUndoManager` grouping per event; merging would need to rewrite a registered action. |
| D21 | Edit-mode typing has its own per-session undo manager. | ⌘Z while editing undoes typing only and never touches model undo with stale text-view state. |
| D22 | Keys map from key codes for special keys and from the current layout's unshifted character for printable keys (US ANSI fallback). | Shortcuts follow the user's layout for letters while arrows, Tab, Return stay positional. |
| D23 | ⌥⌘1…9 on the root changes the canvas structure; on any other topic it sets that branch's structure. | Matches "change branch structure" while giving the root a keyboard path to the canvas layout. |
| D24 | Empty-canvas drag pans in M1; rubber-band selection arrives with drag-and-drop (M3). | Keeps the mouse useful before direct manipulation is built. |
| D25 | Document chrome follows the system appearance; the canvas follows the theme. | Native macOS behaviour; themes colour content, not chrome. |

## M2 · Styling

| # | Decision | Rationale |
| --- | --- | --- |
| D26 | **Node styles are style layers** (a `TopicStyle` per role plus line character) resolved with colour tokens (`branch`, `branch@0.14`, `ink`, `ring@0.2`, `canvas`, `mainBg`, `auto`, hex). | "Implement presets as data" (README §8); users can save a modified preset as a quick style or theme. |
| D27 | **Node styles never change the canvas colour** (Sketch's paper and Glow's dark canvas on artboard NS are pairing suggestions). | Theme supplies colour; style supplies shape (README §8). P0's live `styleLook` works on every theme the same way. |
| D28 | **Auto contrast is on by default** and guarantees the theme's target (AA, or AAA for High Contrast): text is toned toward ink or white; if neither can pass, a solid fill is deepened just enough. | Contrast is a hard requirement for every theme; gap analysis asks for "text colour auto-adapts to background". |
| D29 | Palette id `theme` (new default) means "use the theme's own eight colours"; the six FMT-3 colour themes override it. | Lets Graphite, Paper and the rest keep their designed palettes while colour themes still recolour any theme. |
| D30 | Colour-theme modes: **Rainbow** (next colour per main branch), **Multi** (by sibling position), **Mono** (one colour), **Gradient** (first → last palette colour across main branches). | FMT-3 names the four modes but not their rules. |
| D31 | **Auto balance on** keeps P0's count-based split (ties favour the right); **off** puts every main topic on the right. | Matches P0 and the screenshots; a height-based split moved branches unexpectedly. |
| D32 | **Numbering on a topic numbers its children**; "Apply to siblings" (default on) stores it on the parent so the selected topic and its siblings are numbered. | Matches Xmind's behaviour and FMT-1's "2.1 PRICING" example. |
| D33 | The **Sketch style uses Noteworthy** (ships with macOS) rather than bundling Kalam. | No bundled font or extra licence; Kalam (OFL) can be added later if wanted. |
| D34 | **Skeleton gallery of 24** = FMT-3's nine plus fifteen structure × node style × line pairings. | README §14 asks us to derive the rest. |
| D35 | Custom themes, colour themes and quick styles live in the document's `theme.json` (`StyleLibrary`), and library edits ride on patches so they undo. | Files carry their own look; one undo mechanism. An app-wide library can come with Settings (M8). |
| D36 | Golden snapshots render offscreen with `CALayer.render(in:)` (flipping the hosted root explicitly) instead of capturing the window. | Runs without screen-recording permission or a visible window, so CI can run it. |
| D37 | **Summary and callout topics are real nodes** (`kind` summary / callout) referenced by their element; they never re-parent, and removing the element removes their branch. | They edit, style, undo and export like any topic and can have children (artboard 12), with one code path. |
| D38 | **Connect hints are prefix-free**, so a typed hint is never ambiguous. They're assigned nearest-first from the home row, and typing that matches no hint filters by text. | Artboard 09: "the likeliest target is always one key". Prefix-free sets let two-letter hints exist on large maps without a timeout. |
| D39 | When a Connect filter matches nothing, ↩ **creates the new topic under the central topic**, then connects to it. | Predictable placement; the label opens straight away and the topic can be dragged anywhere afterwards. |
| D40 | **Plain drag on empty canvas rubber-bands; ⌥-drag (and two-finger scroll) pans.** | Rubber-band selection was carried from M1. Trackpad scrolling already pans, so the plain drag goes to selection. |
| D41 | **Stickers are emoji** (`emoji:` asset refs) from a starter set of 80 in five categories; image stickers use the same field with a package asset. | Ships with no artwork licence; "Make a sticker" (Image Playground) lands with AI in M6. |
| D42 | **Rich-text marks only add emphasis** (bold, italic, underline, strike, link) over the topic's style. ⌘B on an already-bold topic beeps; weight is restyled in the Format panel. | A mark that removes emphasis would make the style resolver and exports ambiguous. |
| D43 | **Linked files are referenced, not copied**; dropped images and attachments *are* copied into `assets/` by content hash. | A link means "open that file"; a drop means "keep this with the map". Hashing dedupes. |
| D44 | **Boundaried branches reserve space in the layout** (padding plus a title band), and summary brackets sit outside enclosing boundaries. | Without it a boundary drew over neighbouring topics; spacing is part of the layout, not the drawing. |
| D45 | **Curved relationships bow to the side that crosses fewer topics** unless the user has bent them. | Keeps edges off the central topic (artboard 12) without a router. Elbow routing around obstacles comes with M4's technical canvases. |
| D46 | **Wrapped text is balanced**: the narrowest width with the same line count. | No lone last words in callouts or long topics; it's cheap because measurements are cached. |
| D47 | **Audio notes record locally to m4a; transcription is deferred to M6** (on-device Speech). | Recording needs only the microphone entitlement; the transcript belongs with the local-AI work. |
| D48 | The **floating toolbars are deferred**; their actions are already reachable by keyboard, menus and the Format panel. | Keyboard first. The toolbars arrive with the Insert menu and slash commands. |
| D49 | **Node types live on the node** (`nodeType`, an open enum), not in a canvas-level `diagram.nodeTypes` map as the README sketch shows. Without one, the diagram infers a type. | Types travel with duplicate, move, delete and copy/paste for free; the README calls its JSON a starting point. |
| D50 | **Tree edges are the primary edges of every technical type** (step, data flow, dependency); relationships carry the extra edges; sequence messages are relationships in time order. Edge labels on tree edges are the child's `edgeLabel`. | The artboards' keys already work this way (Tab = "downstream + flow" or "dependency"), and Convert becomes lossless by construction. |
| D51 | DFD, threat model, architecture and sequence draw the **central topic as the diagram's title**; flowcharts draw it as the start step. | Those diagrams have no single root node; the topic still exists, so navigation and undo are unchanged. |
| D52 | **DFD rule set:** (1) a flow must touch a process; (2) every store is written; (3) every process has an input and an output; (4) every flow is labelled (warning); (5) levels are balanced (flow labels touching a process match its next level's boundary flows). Fixes: insert process, reroute via a neighbouring process, ignore (stored per violation). | README §14 asks us to decide beyond artboard 20; these are the standard Yourdon / Gane–Sarson checks. |
| D53 | DFD **numbering is breadth-first** (1.0, 2.0 …; stores D1, D2 …); drilled levels are separate canvases linked by `subCanvas` / `diagram.parent` and number 2.1, 2.2 …. | Numbers follow distance along the flow, as on artboard 20; levels as canvases reuse tabs, undo and export. |
| D54 | **⌘. on a DFD process drills in** (it is Focus on Branch elsewhere); ⌘[ climbs back. | Artboard 20 binds ⌘.; drilling is the DFD's kind of focus, so the key keeps one meaning. |
| D55 | **Threats are nodes** (type `threat`) under the element they threaten. STRIDE category, risk and status are metadata fields; a `mitigation` child records the mitigation. The table is derived. Suggestions are STRIDE-per-element templates marked ✦ until M6. | One model for canvas, inspector and table; the cards stay editable topics; suggestions stay local and deterministic. |
| D56 | Convert's **node-type suggestions are keyword heuristics** (✦), replaced by the on-device model in M6 and kept as its fallback. | Artboard 10 shows suggestions now; M6 owns Foundation Models. |
| D57 | **⌥⌘1–9 follow artboard 18:** Mind, Logic, Org, Timeline, Fishbone, Matrix, Brace, Tree Table, Tree (indented). On the central topic the key also sets the canvas type. | Matches the artboard; the toolbar's type label stays truthful. |
| D58 | **Timeline, fishbone, matrix, tree table and tree are self-contained:** they lay out their whole branch (per-node overrides inside are ignored) and are placed as a block that grows away from the parent. | Lets any branch switch structure (artboard 18, Mixed) without collisions. |
| D59 | **Org charts stack a parent's leaf children** in an indented column (wrapping past 6), and only first-level topics are bordered. | Artboard 18's org chart and its "Leaves stack in columns past 6" note. |
| D60 | **Technical canvases use a deterministic layered layout** (cycle breaking, longest-path ranks, barycentre ordering with boundary groups kept together). There is no free positioning yet. | Keyboard-built diagrams lay themselves out; free layout per canvas (`layout.mode`) is a later opt-in. |
| D61 | Converting to a technical type **remembers the hierarchy structure** (`diagram.previousStructure`) and restores it on the way back; confirmed node types are kept. | map → flowchart → DFD → map returns the same map. |
| D62 | **The slash menu** opens with `/` in Select mode (never changes the text) or as the first character of an empty topic (the typed `/query` is removed on pick). | Notion-style insertion without losing text on existing topics. |
| D63 | **`/math` is a LaTeX-subset typesetter** in Core Text, not a web engine; **`/code`** highlights common keywords across Swift, JS, Python, Go, Rust and SQL. The editor always shows source. | Local, small and fast; the formats are stored as plain text plus `textFormat`. |
| D64 | **Sequence message keys** (Tab, ↩, ⌥↩, ↑↓ on a selected message) are element keys, like M3's element Space / Delete, not registry commands. | Keeps ⌥↩ free in other scopes (it adds a child in the Outliner profile and replaces in Find). |
| D65 | **Architecture edges default to a protocol** from the target's type (db → SQL · 5432, cache → RESP, queue → AMQP, service → gRPC, external → HTTPS), with suggestions while editing. | Artboard 22 and README F3 ("labels default to protocol"). |
| D66 | On technical canvases, **relationships are restyled when drawn**: the theme colour becomes the neutral arrow, and pill labels become plain or boxed. Stored data is unchanged. | Flows read as flows, and converting back to a mind map restores the original look. |
| D67 | **View state is not document state.** Focus, the active filter, search highlights, tag highlights and the current slide never enter the file or undo. Saved filters, H (hide from slides) and deck settings are saved, and undoable. | "Selection survives every switch" without polluting history; files stay diff-friendly. |
| D68 | The **palette hides commands that can't run** and ranks recent (per user, not per document) first, then fuzzy: prefix > word start > anywhere > subsequence. The top row is what ↩ runs. | Artboard 25's three rules. |
| D69 | **Quick-jump paths start with the canvas title**, which stands for the central topic. | "Platform reference › VPC › Private subnet" on artboard 25. |
| D70 | **The outline is an AppKit view with its own key scope** (↩ sibling, ⇥ indent, ⇧⇥ outdent, ↑↓ rows, ←→ fold / parent / child); other keys fall through to the canvas commands. Notes edit inline by clicking. | Outliner keys differ from the map's (Tab indents rather than adding a child), and the conflict checker stays per scope. |
| D71 | **Focus lays the branch out as its own map where it stands** (root look) and blurs the rest. Esc climbs one level; ⌘. on a DFD process still drills (D54). | "The branch becomes the whole map" (artboard 27). |
| D72 | Filter **Hide draws non-matches at 5% opacity** rather than removing them. | The layout and camera stay still while you refine a filter. |
| D73 | **Canvas overlays follow the canvas theme's appearance** (light map → light chrome), not the system's. | On a Classic map in system dark mode the palette was unreadable. |
| D74 | **Slide export:** PDF (one 1920 × 1080 page per slide); PowerPoint .pptx (one full-bleed image per slide, title as alt text); Keynote opens the same .pptx, because Keynote's own format is undocumented; video is H.264 MP4 at 1920 × 1080, 30 fps, 3 s per slide, with 0.6 s cross-fades. | README §14 asks for a video codec decision; H.264 MP4 plays everywhere. Image slides keep every theme exact. |
| D75 | **Deck rules:** a title slide, then one per main topic (hierarchies), one per flow in breadth-first order (technical types with step-through-flow), or one per message (sequence). Step numbers count only slides that play. | "Auto slides" on artboard 32; DFD steps follow the data. |
| D76 | **The presenter view opens automatically on a second display;** P toggles it (floating) on a single display. | Artboard 32 shows "Display 2"; on a laptop it must not cover the slides unasked. |
| D77 | The **slide theme (dark / light) swaps to the canvas theme's counterpart** while presenting only. | Slides can be dark for a talk without restyling the map. |
| D78 | **`AIEngine` is a protocol in NexusCore**; `AppleEngine` (NexusAI) is the default and `ScriptedEngine` drives every test and preview. The controller checks `availability` before each entry point. | Flows are deterministic in CI without a model; the live engine is tested only for latency. |
| D79 | **Chats are document-level, outside undo**, stored in `ai/chats.json` (only when there are any) and filtered by canvas. | Undoing an edit must never lose a conversation; the canvas files stay unchanged for maps without chats. |
| D80 | **Ghosts are scene-only pseudo-nodes** (`ghost:N`) injected into a copy of the canvas before layout, so they lay out exactly like children. They are never in the model, the file or undo. Plan previews reuse them. | One layout path, and nothing can be applied by accident. |
| D81 | **Ideas stream through guided generation** (`IdeaList` partials): each ghost is emitted when the next one starts. A prewarmed session is kept for the next request. | Meets the 1.5 s first-ghost budget (1.0–1.3 s measured) without unguided text parsing. |
| D82 | **MLX / Core AI and localhost models are shown but disabled in v1.** | A localhost server needs `com.apple.security.network.client`, which would weaken "zero outbound connections"; MLX needs a model-loading story. Neither belongs in the first local-AI milestone. |
| D83 | **Translation uses installed language pairs only** (`TranslationSession(installedSource:target:)`). A missing pair shows how to install it, and the sheet's preview says so. | Downloading a pair is a system action; OpenNexus never triggers network use itself. |
| D84 | **Translated and masked maps are new canvases**; the original stays. "Keep both" background removal adds the cut-out as an attachment, and "Replace original" swaps the image. | Reversible by construction, and safe to share. |
| D85 | **A free-form panel question returns an answer plus an optional plan**; only the text actions (Summarize, Explain, Write it up, Diagram as code) stream plain text. Discussion mode drops any plan. | The panel's purpose (artboard 28) is "ask, then review a diff". |
| D86 | **The heuristic suggestions from M4** (Convert node types, STRIDE templates) stay as they are and remain the fallback when AI is off. | Entry points never disappear (artboard 29). |
| D87 | **"Suggest ideas after a pause" (off by default)** shows ghosts 1.5 s after a new topic is named, if nothing else changed. It stays silent when the model can't run. | Ghosts must never interrupt typing; explicit entry points already explain availability. |
| D88 | **Style environments precompute each role's base layers** (defaults → theme → node style) once. | These were rebuilt, with colour-to-hex formatting, for every node on every reflow, and made reflow 5× slower than M1. |
| D89 | **Interchange formats live in a pure `NexusInterchange` target**; zip reading and writing (raw deflate through Foundation) live in NexusFormat. | Every importer and exporter is golden-tested headless, and the CLI (M9) can reuse them. No third-party code. |
| D90 | **Importers build an intermediate tree (`ITopic` / `ICanvas`) and `CanvasBuilder` resolves references**, so relationships, boundaries, summaries, callouts and internal links work the same for every format. The report counts what came in and lists what didn't, by kind, with counts. | One validated path to canvases, and an honest report (artboard 33). |
| D91 | **Xmind specifics:** task pies become progress markers; markers without an equivalent are dropped and reported; extensions (task dates, audio) are reported; nested sheet copies under numeric keys are imported once each; zero-byte cloud placeholders are reported as "download it first" and never read. | Matches what real files contain (33 of this Mac's files import cleanly). |
| D92 | **Imported internal links become `nexus:topic/<canvas>/<node>` links**; merged or pasted canvases get fresh ids, with links, sub-canvas and level references rewritten. | Links keep working wherever the canvas lands. |
| D93 | **`Patch` carries canvas-set changes** (whole canvases before and after, plus the tab order). New, duplicate, delete and paste canvas, merge, import, translated and masked copies, DFD levels and snapshot restore are each one undo through `store.commit`. Assets are append-only within a session. | "Every change undoable", with one mechanism; orphaned assets are harmless and content-addressed. |
| D94 | **Topic copy writes a canvas fragment** (private pasteboard type) **plus indented text**. Paste prefers the fragment; otherwise Markdown, OPML, Mermaid, PlantUML or indented text becomes a branch, and a single line becomes one topic. A root the parser made up to hold several top-level topics is dropped on paste. | Copy and paste between maps is lossless, and pasting from other apps does what the brief says. |
| D95 | **Visual exports render the canvas's own layers offscreen at the export zoom**; branch and selection scope hide everything else in the scene without re-laying it out. Bitmaps are capped at 16,384 px per side. | Exports look exactly like the map, with the same colours and positions, and text is sharp at 4×. |
| D96 | **SVG is written from the scene.** "Embed fonts" keeps live `<text>` with the system font stack (Apple's system fonts can't be embedded under their licence); "Outline text" converts glyphs to paths. Position and font sit on `<text>`, which AppKit's renderer needs. `data-nexus-*` attributes carry types and fields. | Editable or exact, the user's choice; it renders in WebKit, AppKit and browsers. |
| D97 | **PDF export and print place a 3× rendering of the map** in vector pages, at fit, actual size or tiled with cut marks, plus an outline mode and a notes appendix. Printing hands the PDF to PDFKit's print operation. | One layout for preview, Save as PDF and print; map text isn't selectable, which is acceptable for v1. |
| D98 | **Encryption:** AES-256-GCM (CryptoKit) over a zip of the ordinary package, with the key from PBKDF2-SHA256 at 600,000 iterations. The readable manifest keeps the format, the canvas ids, the KDF parameters and the hint. The Keychain entry is keyed by the salt. A document that isn't unlocked is written back byte-for-byte. | Nothing sensitive is readable without the password; a cancelled unlock can't damage the file. |
| D99 | **Recovery snapshots** are zipped packages in Application Support, taken every five minutes while edited and on close. The newest 20 are kept, sealed with the document's key when it's encrypted. Restore is one undo. NSDocument's versions stay as File › Revert To › Browse All Versions. | Replaces Xmind's File Cache (artboard 50) without touching the document folder. |
| D100 | **Map Shot saves to a folder chosen on first use** (the panel opens on Desktop) and remembered as a security-scoped bookmark, which needs the `files.bookmarks.app-scope` entitlement. ⌥↩ only copies. | The sandbox can't write to Desktop silently; asking once keeps "Copied and saved" true afterwards. |
| D101 | **Markdown export defaults to headings for the central and main topics, then nested bullets**, with to-dos, labels, priority and links in a form the importer reads back. | Readable documents, and the round trip is lossless for structure. |
| D102 | **The export sheet remembers its settings per format** (UserDefaults), including when you switch between formats. | Artboard 30: "last used settings remembered per format". |
| D103 | **Settings are a declarative schema** (`SettingsSchema`) rendered by one view, stored in an injectable `Preferences` over UserDefaults that posts a change per key. Canvases observe it and re-apply live. | One source for the panes, search, defaults and tests; every row is searchable and testable without UI. |
| D104 | **Rows that would need the network are shown, off and locked** (update checks and installs, channel, usage statistics, crash-report sending, link previews), with a tooltip saying why. The network log reads "0 requests". | Matches the artboards' inventory while keeping README §12: OpenNexus v1 makes no network requests and has no network entitlement. |
| D105 | **Integrations settings persist now and act in M9.** | The pane is part of M8's acceptance; the features belong to the integrations milestone. |
| D106 | **Hyper is Right Option held (no permission needed); Caps Lock arms a sticky Hyper for the next key; a tap alone sends Esc.** Remapping Caps Lock itself needs Input Monitoring, which the Hyper card explains before anything is asked. | A clash-free namespace that works on first launch, without a system prompt. |
| D107 | **⇧⌘N chooses a type only inside Home**; elsewhere ⇧⌘N stays New Note. | The standard map already binds ⇧⌘N; Home is where a type picker is useful. |
| D108 | **Single-JSON documents are a second document type** (`.nexusjson`, conforming to public.json) with optional embedded images. | Diff-friendly single files for people who want them, without changing the package format. |
| D109 | **AI chats are kept in the document, on this Mac, or not at all** (Settings › Privacy), and can be removed from exports. | Chats may hold content the user wouldn't share with the file. |
| D110 | **Touch ID unlock is asynchronous**, followed by the Keychain password; encrypted documents can lock after idle. | A synchronous wait for LocalAuthentication on the main thread could deadlock. |
| D111 | **The tour runs in a real document and follows real commands and edits**, not scripted screens. ⌥⌘T in the tour converts straight to the role's type; lesson 6 uses scripted ideas when Apple Intelligence is off; the map is kept as "My first map". | Brief: "a real canvas you build, not a slideshow"; every lesson must always be completable. |
| D112 | **Tips count mouse uses per command and show the key on the third**; any key press clears the tip. | Teaches keys at the moment they'd help, without nagging. |
| D113 | **Fonts are cached per face** (family, size, weight, italic, CJK fallback), and spoken descriptions compute depths in one walk. | Restores the 16 ms key-to-caret budget after the CJK cascade and VoiceOver descriptions made it 43 ms. |
| D114 | **A file changed on disk is merged, not reverted.** A three-way merge (base = last read or written) takes each canvas, topic and setting from the side that changed it. Where both sides changed the same one, the user's version wins and is named in the toast. It arrives as one undo step ("Change on Disk"). | NSDocument's default silent revert would wipe undo; README: "every agent edit is one undo step". |
| D115 | **Signing comes from `App/Config/Base.xcconfig`,** with an optional gitignored `Signing.local.xcconfig` naming a team. Ad hoc otherwise. One App Group, `$(TeamIdentifierPrefix)com.opennexus`, is shared by the app, the extensions and the CLI; team-prefixed groups need no provisioning profile. ## M25 · Xmind style fidelity

| # | Decision | Rationale |
| --- | --- | --- |
| D217 | **Boundaries and summaries carry their styles in Xmind's keys, in both `.xmind` and XMind 8.** A boundary writes `line-color`, `line-pattern`, `line-width`, `shape-class` (`roundedRect`, `rect`, `scallops`, `waves`, `polygon`) and `svg:fill` / `fill-pattern`; a summary writes `line-color`, `line-width` and `shape-class` (`org.xmind.summaryShape.curly`, `square`, `round`). XMind 8 puts them in `styles.xml` as `boundary` and `summary` styles named by `style-id`. Each element writes only what differs from the theme's classes, which now hold OpenNexus's defaults: a solid ring-coloured boundary (M18 wrote it dashed, which the canvas never drew), an ink summary with a curly bracket, a curved relationship ending in an arrow. The fill is the boundary colour at its fill opacity mixed over the canvas, with the line colour beside it; the importer solves for the opacity that best gives that fill. Near shapes (stadium, ellipse and corners boundaries, a line bracket), a boundary's technical meaning and its title position are reported; Xmind's `tension` boundary reads as rounded and `angle` bracket as curly. | Xmind wants opaque colours (D185) and keeps line and fill apart, while OpenNexus draws the fill in the line colour; writing both lets a round trip recover the opacity to the hundredth. Theme classes that match the canvas mean a default boundary needs no properties of its own and looks the same in Xmind. |
| D218 | **OpenNexus keeps what Xmind can't hold in an `org.opennexus.style` extension.** On a sheet: the level styles (`levels`, by depth, as in `.nexus`) and, when the theme is written untagged (D211), the OpenNexus theme and the theme id written (`theme`, `themeId`). On a topic: its built-in quick style (`quickStyle`), its own style with colour tokens unresolved (`style`) and a fingerprint of the properties written (`written`). The resolved properties are still written, so Xmind draws the same thing. A topic's record is written only when its properties alone wouldn't read back as its quick style and own style: a level or quick style applies, or the style has tokens (`branch`) or things Xmind can't draw. XMind 8 carries the same JSON as the text of an `<extension>`'s `<content>`, on the sheet and on topics. | Xmind preserves extensions it doesn't know, by provider, and the importer already skips those it doesn't use. Writing the record only where it adds something keeps ordinary files unchanged and small. Level styles belong to the canvas, so they ride on the sheet; quick styles and tokens belong to the topic. |
| D219 | **A record is used only while it still describes the file.** A topic's record applies when the fingerprint matches the topic's current properties; otherwise the properties win, so a style changed in Xmind isn't overwritten. A sheet's theme applies only while the sheet's theme id is the one written, so picking another theme in Xmind brings in that theme. Level styles always apply. A custom quick style isn't in the importing document's library, so it's written merged into the topic's own style rather than by name. | Xmind keeps the extension through edits it doesn't understand, so a stale record must not undo the user's work. A fingerprint of the written properties is the cheapest test that nothing changed. Level styles are OpenNexus-only and have no Xmind counterpart to go stale against. |
| D220 | **Another app's theme classes for boundaries, summaries and relationships import onto each element:** the class's properties sit under each element's own, then map as in D217 and D185. Themes OpenNexus wrote (tagged, or named by a record) are skipped, since their classes are OpenNexus's defaults. The import report no longer lists "Xmind theme's boundary, summary and relationship styles". | The elements an Xmind map has look as they did in Xmind, with no new model: every property the classes set already has a field on the element. Skipping OpenNexus's own theme keeps a round trip from stamping defaults onto every element as fixed colours. |
| D221 | **No canvas-level default for boundary, summary and relationship styles.** M23 added `style.colors` and `style.roles` because topic styles resolve through `StyleEnvironment`; boundaries, summaries and relationships take their defaults from the theme inside the canvas renderer, so a canvas-level setting would need new resolution in the renderer, the Format panel and new-element commands. Elements added after an import use the OpenNexus theme's defaults. | D220 already gives imported elements their look, which is what an imported map needs. A canvas-wide element default is a theme feature that would touch the canvas UI other work is changing; it's recorded as a known gap. |

## M29 · Image import and Markdown tasks

| D237 | **A fishbone's sub-causes are lines tucked under a cause and set back from its bone.** Before the plain fit (D192), lines stacked under the nearest line above on their side of the spine (across from it, at most 1.2 lines below) whose end nearest the bone sits half a line or more behind that line's, or level with a line that is itself one, are candidates.
