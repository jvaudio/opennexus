# M22 · Tasks and comments in formats and agents

## Plan

**Goal (closing M11's and M14's format and agent gaps):** a topic's task fields (M11) and
its comments (M14) survive OpenNexus's other formats and its agent tools, and an AI work
breakdown fills in task dates when its plan has them.

**Accept when:**
- **A1 · Markdown:** export and import carry every task field and dependency, in a
  readable syntax, and the Comments appendix reads back onto its topics. A round trip
  keeps tasks and comments exactly.
- **A2 · OPML:** task fields and comments are namespaced outline attributes that other
  readers ignore, and round-trip exactly.
- **A3 · MindManager import:** start, due, duration, progress, resources, priority and
  dependencies become task fields, as Xmind's do (D149).
- **A4 · Excel export:** Owner, Start, Due, Progress and Depends on columns when a canvas
  has tasks, and a Comments column when it has comments; the existing columns stay.
- **A5 · Agents:** `nexus` and `read_map` print task fields and comments; MCP tools set task
  fields and dependencies and add comments, marked as AI (D121) and needing edit access
  (D116).
- **A6 · AI plans:** a work breakdown's dates and lengths become task fields on accepting;
  a plan without them makes undated tasks.
- **A7 · Quality bars:** no new chrome strings outside Loc (the catalog is regenerated), no
  network APIs, no package dependencies, and `.nexus` files are unchanged.

### Markdown (D205, D207)

- **A to-do line ends in task tokens**, each written only when set, in this order:

  ```markdown
  - [ ] Beta · Nov @Ana 2026-11-02→2026-11-06 40% ^n13
  - [ ] GA · Jan @[Ana Lee] →2027-01-15 after:^n13
  - [ ] Pro (P1) 2026-11-09→ after:^n13(SS+2)
  - [x] Newsletter @Sam
  - [ ] Raise to \40%
  ```

  - `@Ana`, or `@[Ana Lee]` when the owner has spaces;
  - `start→due` (`start→` or `→due` for one; `->` is read too);
  - `40%`, the stored progress (done is the check box);
  - `after:` the predecessors' anchors, each with `(SS+2)`-style kind and lag unless it's
    plain finish-to-start;
  - `^n13`, the topic's own anchor, written only on topics that other lines name.
- **Reading:** tokens are taken from the end of a line with a check box, each kind once; an
  anchor from any line. A token that doesn't parse stays text. A to-do title that would
  read as a token gets a `\` before it on export, which the importer removes.
- **The Comments appendix** now writes each date as stored and an anchor for a repeated
  title (`- **Pricing** ^n30 · Kim · 2026-10-22T08:15:00+02:00: Which pricing?`). The
  importer reads it back when every line of the section is a comment line.

### OPML (D206)

`<opml version="2.0" xmlns:nexus="https://opennexus.app/ns/opml">`, declared only when a
topic uses it. Attributes: `nexus:id`, `nexus:start`, `nexus:due`, `nexus:owner`,
`nexus:progress`, `nexus:priority` (to-dos), `nexus:after` and `nexus:comments` (compact
JSON). Read under any prefix bound to the namespace.

### MindManager (D208)

`<ap:Task>` attributes and `Dependency` children, and relationships marked as dependencies,
become `ITask`s; `CanvasBuilder` resolves them like Xmind's.

### Excel (D206)

`ExcelFormat.taskColumns` and `commentColumns`, after the existing (and technical) columns.
Widths and wrapping are looked up by column name.

### Agents (D209)

- `read_map` and `nexus read`: a `task:` line and `comment by …:` lines under each topic.
  `nexus read --tasks` lists only tasks. `nexus import` counts tasks, dependencies and
  comments.
- MCP `set_task` (start, due, duration, owner, progress, priority, done, after) and
  `add_comment` (text, author), both edit-access tools.

### AI plans (D209)

`GhostIdea` gains `start`, `due` and `workingDays`; `GhostIdea.scheduled` works out the
dates on the canvas's calendar, and accepting makes a to-do with them. The Apple engine's
breakdown asks for the first phase's start date and turns each phase's weeks into working
days.

### Built

- **NexusInterchange:** `TaskMarkup` (the dependency list codec, Markdown task tokens,
  escaping, `ITopic.update(ref:)`); Markdown task tokens, anchors and appendix import;
  OPML `nexus:` attributes; `MindManagerTask`; Excel task and comment columns.
  `CanvasBuilder` now resolves dependencies for successors without a ref.
- **NexusAgent:** `MapTools.taskLine`, the outline's task and comment lines, `set_task`,
  `add_comment`, the client name for comment bylines; `nexus read [--tasks]` and import
  counts.
- **NexusCore:** `GhostIdea.start`, `due`, `workingDays`, `isTask` and `scheduled`.
- **NexusCanvas:** accepting ghosts makes dated tasks.
- **NexusAI:** the breakdown asks for a start date and yields working days.

### Changed from the plan

- **The Markdown appendix's dates** are now full timestamps (D207 amends D162's format), so
  comments round-trip exactly. Word keeps the short date.
- **OPML writes priority on to-dos**, so `launch.opml`'s golden gained the namespace and
  `nexus:priority="1"` on Pro.
- **Comments added by agents don't mark the topic AI**; the byline says "(AI)" instead.
- **The CLI had no read command**, so `nexus read` was added rather than extending one.
