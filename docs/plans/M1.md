# M1 · Canvas and keyboard core (F1)

## Plan

**Goal:** the document window from P0 / S3 with a real AppKit canvas: Select and Edit
modes with the state pill, Xmind's create / edit / navigate / restructure keys, mind-map
and logic-chart auto-layout, fold, undo, autosave, the ⌘-hold cheat sheet and the toolbar.

### Architecture

```
NexusDocument (NSDocument) ──owns──▶ DocumentStore ◀──reads/commits── CanvasController (@Observable)
        │  NSUndoManager ◀─registers patches─┘                               ▲         │ scene
        ▼                                                                    │ keys    ▼
DocumentWindowController ── toolbar, canvas tabs ──▶ CanvasHostView ── CanvasView (layers) + NodeTextEditor
                                                        └─ SwiftUI overlays: state pill, hint bar, toast, cheat sheet
```

- **`DocumentStore`** (NexusCanvas): holds the `DocumentModel`, applies patches, and
  forwards each one to an `UndoRegistrar` (NSUndoManager in the app, `UndoStack` in tests).
  Observers (controllers) hear about every applied patch, including undo/redo.
- **`CanvasController`**: the headless brain. Mode state machine (Select / Edit), the
  selection, the edit session (text, select-all, placeholder), command handlers bound by
  `CommandID`, spatial navigation, toasts. No AppKit views, so the keyboard flow is
  testable without a window.
- **`SceneBuilder`**: canvas + theme → measured sizes (CoreText, cached) → `TreeLayout`
  frames → scene (node looks, branch colours, edges). Pure and benchmarked.
- **`CanvasView`**: layer-backed view. One `NodeLayer` per visible node (shape + CoreText
  text layer that draws with the same attributes used to measure), one `CAShapeLayer` per
  branch line. A display-link `Animator` steps `snap` springs per node; branch paths are
  recomputed from animated frames every frame, so lines stay glued to nodes and new input
  retargets springs in flight. Reduce Motion swaps movement for a 150 ms cross-fade.
- **`NodeTextEditor`**: an `NSTextView` placed over the edited node (scaled with zoom)
  with a private undo manager. Return / Esc commit, Tab commits and adds a child, ⇧↩
  breaks the line, ⌘↩ commits and adds a parent; IME marked text is never intercepted.
- **Typing never waits:** a create command inserts the node, lays out synchronously (well
  under 1 ms for typical maps), puts the caret in the node's final frame in the same event,
  and only then animates the node growing from its parent's connector.
- **Menus** are generated from `CommandRegistry` (nil-targeted actions carrying the
  command id); the canvas validates them by mode, so plain-key equivalents never steal
  keys from the text editor.

### Tests

- Scripted keyboard test (NexusCanvasTests): drives a real `CanvasView` in an offscreen
  window with synthesized key events and builds a 20-topic, 3-level map using only keys
  (Tab, Return, ⇧Return, ⌘Return, arrows, ⌥⌘↑↓, ⌘/, Space, typing).
- Controller tests: every create / restructure key, Space vs typing, commit rules, Esc,
  fold, undo / redo through the store.
- Spatial navigation picks the nearest node in each direction.
- Performance: key → caret under 16 ms (measured around the real key path); 1,000-node
  reflow under 50 ms; also recorded with `os_signpost`.

Known gaps carried forward:
- The XCUITest variant of the F1 test is not added yet: driving the app needs Accessibility
  permission that was not granted in this session. The headless key-event test covers the
  same path minus the menu bar.
- Undo/redo and autosave were verified headless and by build; not yet exercised by
  driving the live app.
- Drag-and-drop reparenting, rubber-band selection and Space-drag pan (brief §5) are not
  built; empty-canvas drag pans for now.
