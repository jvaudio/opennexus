# M18 · Xmind parity: element relationships, styles, XMind 8

## Plan

Three gaps left by M15 and M16:

1. **Relationships to boundaries, summaries and callouts** (M16's known gap). Xmind lets a
   relationship end on any of them; OpenNexus ends were topics and zones only.
2. **`.xmind` styles and themes** (D166). Export left Xmind's default look; per-topic styles
   and the canvas theme didn't travel.
3. **XMind 8 export.** M15 wrote only a notice in `content.xml` (D167).

**Accept when:**
- **B1 · Model:** a relationship can end on a boundary or a summary, survives save and load,
  undo, repair and merge, and goes away with the element. A callout's bubble is a target.
- **B2 · Canvas:** the scene anchors these ends, Connect mode offers them as targets and
  sources, and VoiceOver names them.
- **B3 · Exports:** SVG, slides and the scoped image exports, Mermaid, PlantUML, draw.io,
  the agent tools, `.xmind` export and Xmind import all carry them.
- **B4 · Styles:** the canvas theme and per-topic styles (fill, border, shape, font, colour,
  line) go to Xmind's style JSON as far as it can express them, come back through the
  importer, and the rest is reported.
- **B5 · XMind 8:** an export option writes topics, notes, labels, markers, relationships,
  boundaries, summaries and task info as XMind 8 stores them, and it round-trips.
- **B6 · Well formed:** every archive, JSON and XML part parses; output is byte-stable.

### 1. Element ends

**Model (D180, D181).** `RelationshipEnd` gains `.boundary(id)` and `.summary(id)`. The file
keeps the id in `from` / `to` and writes `fromKind` / `toKind` (`boundary`, `summary`) only
for a non-topic end; both schema copies list the kinds. A kind from a newer build reads as a
topic id, which repair drops. A callout's bubble and a summary's own topic are already
topics, so they stay `.topic` ends: a separate `callout` kind would have been a second name
for the same thing.

- `Canvas.has` checks the new kinds, so validation and merge cover them.
- Repair drops relationships to missing ends *after* trimming boundaries, so a boundary that
  repair empties takes its relationships too.
- Removing a boundary or a summary, or deleting the topics they hang on (a boundary loses
  all its topics, a summary loses its range), removes their relationships in the same undo
  step.
- Copy and paste carry a relationship when every end travels: topics of the branch, and
  boundaries and summaries that are copied with it. Copying now includes a summary over
  copied siblings together with its topic's branch (it was dropped before).

**Canvas (D184).**
- The scene builds boundaries before relationships. A boundary end anchors on the
  boundary's rectangle, a summary end on its bracket, through the same routing as topics
  (6 pt gap; a topic inside the boundary draws to the nearest edge). "Source" colour from a
  boundary or summary uses its colour.
- Branch, selection and zone exports keep a relationship when both its ends are still
  drawn.
- Connect mode (⇧⌘L) ranks boundaries and summary brackets with topics and zones, with hint
  chips at their corners. The filter matches "Boundary: title" (or its first topic when
  untitled) and "Summary: topic text". A selected boundary or summary is the source.
- VoiceOver, the outline and "read edges" name ends by kind: "Risks to boundary Reach",
  "summary Paid plans to callout Ask legal". The Connect rotor lists boundaries and summaries.
- SVG metadata writes `data-nexus-from-kind` / `-to-kind` for any non-topic end.

**Text formats (D182).** Boundaries that relationships end on become groups named
`boundary_<id>`: Mermaid subgraphs and PlantUML rectangles, nested by containment with the
zones (each topic is declared once, in its innermost group), and draw.io cells behind the
topics. A summary end points at the summary's own topic, the nearest thing those formats
have. Without element ends the output is unchanged.

**Agent tools.** `add_edge` takes `boundary:<id or title>` and `summary:<id or topic text>`
as well as `zone:`. `read_map` lists boundaries and summaries with their ids and names ends
as `Title [boundary:b1]`.

**Xmind (D183).** Import resolves a relationship that names a boundary (in the main tree or
a floating branch) or a summary to that end. This replaces D172's conversion of a floating
boundary to a zone, which existed only because boundaries couldn't be ends. A relationship
naming a callout's or a summary's topic id ends on that topic. `.xmind` export writes
boundary and summary ids, so the round trip keeps these relationships.

### 2. Styles and themes (D185, D186)

`XmindStyle` (NexusInterchange) maps between OpenNexus styles and Xmind's style properties
(the same keys XMind 8's `styles.xml` uses). `NexusInterchange` now depends on `NexusTheme`,
an internal target, so the writer resolves themes, quick styles, palettes and branch colours
exactly as the canvas does (the custom ones come from the document's own style library).

| OpenNexus | Xmind property |
| --- | --- |
| Shape | `shape-class`: roundedRect, rect, ellipserect (pill), ellipse, circle, diamond, parallelogram, hexagon, cloud, underline; squircle, ring pill, double and hand-drawn written as the nearest one |
| Fill, fill colour | `fill-pattern` (`solid`, `none`), `svg:fill` |
| Border, width, colour | `border-line-pattern` (`solid`, `dash`, `dot`), `border-line-width` (`0pt` for none), `border-line-color` |
| Font, size, weight, italic | `fo:font-family` (serif → Georgia, mono → Menlo, rounded → SF Pro Rounded, hand → Chalkboard SE), `fo:font-size`, `fo:font-weight` (normal, 500, 600, bold, 800), `fo:font-style` |
| Underline, strikethrough, case, alignment, text colour | `fo:text-decoration`, `fo:text-transform`, `fo:text-align`, `fo:color` |
| Branch line shape, colour, width, dash | `line-class` (curve, straight, elbow, roundedElbow), `line-color`, `line-width`, `line-pattern` |
| Relationship line, caps, dash, width, colour | `shape-class` (curved, straight, angled), `arrow-begin-class` / `arrow-end-class` (none, spearhead, triangle, diamond, dot, square), `line-pattern`, `line-width`, `line-color` |

- **Per topic:** the topic's level style, quick style and own overrides, merged, become its
  `style.properties`. Colour tokens (`branch`, `ink`, `x@alpha`) are resolved to opaque hex.
  The theme's part isn't repeated on every topic.
- **Theme:** each sheet gets `theme` with id `opennexus.<theme id>`: `map` (background,
  `multi-line-colors` from the palette, tapering) and one property set per topic class
  (central, main, sub, floating, summary, callout), plus boundary and relationship colours.
  Canvas-wide font and branch-line overrides are folded in.
- **Import:** topic and relationship properties come back as styles. A theme OpenNexus
  wrote imports as that theme, with the background, font and line shape when they differ
  from it. Another app's theme keeps its background and central-topic font, and the import
  report says OpenNexus's theme is used.
- **Report:** the blanket "Theme, colours and topic shapes" line is gone. What Xmind can't
  hold is listed: shadows, corner radii, tint and gradient fills, shapes and arrows without
  an equivalent (or written as a near one), wrap width and spacing, numbering, line caps,
  tapering and glow, relationship label placement and bends, colours that follow the
  source, and node style or colour mode settings.

### 3. XMind 8 export (D187, D188)

- **Where:** the export sheet's Xmind section has a "Xmind 2020 or later / XMind 8" choice,
  remembered with the format. `nexus export --to xmind8` (alias `xmind-8`) and the MCP
  `export` tool do the same. Saving says "Saved for XMind 8".
- **How:** the Zen writer builds the sheets once; `XmindWriter.exportXMind8` writes them as
  XMind 8 XML, so both exports carry the same content and report.

  | Path | Holds |
  | --- | --- |
  | `content.xml` | sheets: topics (title, `position`, `notes` with plain and XHTML, `labels`, `marker-refs`, `xhtml:img`, `xlink:href`, `branch`, `structure-class`, `style-id`), `children/topics` typed attached, detached, summary and callout, `boundaries`, `summaries`, the `org.xmind.ui.taskInfo` extension; `relationships`; the sheet `title`; `legend` |
  | `styles.xml` | topic and relationship styles, and the theme in `master-styles` |
  | `comments.xml` | `<comment object-id author time><content>` |
  | `meta.xml`, `META-INF/manifest.xml` | creator; every file |
  | `attachments/` | images and attachments (XMind 8 keeps both there) |

- **Task info:** `status`, `start-date`, `end-date` (epoch milliseconds at noon, D168),
  `assigned-to`, `progress` (0–1) and `prerequisites/prerequisite id type lag` (lag in
  milliseconds): the names the importer already reads (D149).
- **Importer additions:** XMind 8 callouts (`topics type="callout"`), `styles.xml` (topic and
  relationship `style-id`s and the sheet's theme), so the export round-trips.

### Built

- **NexusCore:** `RelationshipEnd` kinds, `Canvas.has`, repair order, element removal,
  copy and paste of element ends, `EndGroup` / `Canvas.endGroups()` and `textRef` for text
  formats.
- **NexusCanvas:** scene anchoring and boundary order, Connect targets and sources,
  `Canvas.spokenName` for VoiceOver, the outline and "read edges", SVG metadata, the export
  sheet's XMind 8 choice.
- **NexusInterchange:** PlantUML and draw.io groups, Xmind import of element ends,
  `XmindStyle.swift` (styles and themes, both ways), `XmindLegacyExport.swift` (XMind 8),
  the XMind 8 importer's callouts and `styles.xml`.
- **NexusAgent:** `boundary:` and `summary:` ends, `read_map` sections, `xmind8` format.
- **Package:** `NexusInterchange` depends on `NexusTheme`.

### Changed from the plan

- **No `callout` end kind.** A callout's bubble is a topic, and Connect, the scene, exports
  and Xmind already treated it as one; the work there was to test it and to have VoiceOver
  say "callout …".
- **D172's boundary-to-zone conversion is gone.** With boundary ends, an Xmind boundary
  stays a boundary, and `.xmind` round trips keep it.
- **XMind 8 export writes styles too**, since XMind 8's `styles.xml` uses the same property
  keys as Zen.

### Defects found and fixed

- **Copying a branch dropped summaries over its siblings** (the summary's topic isn't a
  child, so the fragment never held it).
- **draw.io export left out topics under floating, summary and callout topics** when the
  canvas layout didn't give them boxes, so relationships to them pointed at missing cells.

### Known gaps

- **Not opened in Xmind or XMind 8 itself.** The files follow what the importer reads and
  what open-source parsers document. The least certain names are the shape classes
  `hexagon`, `cloud` and `ellipserect`, the relationship shape `angled`, the arrow classes,
  and XMind 8's `taskInfo` element names and theme layout. `NEXUS_XMIND_OUT=<folder> swift
  test --filter writeSample` now writes the Zen sample, the XMind 8 sample and a styled
  sample to check by hand.
- **Boundary styles** (colour, shape, dash) aren't written to Xmind yet; boundaries use the
  theme's colour.
- **Round trips flatten some styling:** level styles and quick styles come back as each
  topic's own style, and `branch` colours as fixed hex.
- **Another app's theme** imports only its background and central-topic font; its branch
  colours (a palette) and topic-class styles don't, since palettes live in the app's library.
- **XMind 8 and newer layouts:** tree table, matrix, brace and timeline classes are written
  as in Zen files; XMind 8 shows its default layout for classes it doesn't know.
- **Summary ends in Mermaid, PlantUML and draw.io** point at the summary's topic, so they
  re-import as topic ends; boundary groups re-import as M16 describes for zones.
- **Duplicate** copies topics only, without boundaries, summaries or relationships
  (unchanged; D170 says otherwise). Pasting a summary keeps its topic but not that topic's
  children (unchanged).
- **Xmind 26.03 zones** still aren't read (M16).
